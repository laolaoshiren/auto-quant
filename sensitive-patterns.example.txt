# 站点专属敏感信息规则（示例）
#
# 复制本文件为 `sensitive-patterns.txt`（已被 .gitignore 忽略），填入你自己的
# 私有信息，然后运行 `pwsh -File scripts/install-hooks.ps1` 安装钩子。
#
# ---------------------------------------------------------------------------
# 为什么这个文件本身只是示例、真名文件不入库
# ---------------------------------------------------------------------------
# 这个仓库要防止的是「把站点专属信息写进代码」——域名、服务器 IP、主机名、
# 内网地址之类。如果把这些真实值提交进仓库来"让检查生效"，那检查配置本身
# 就成了泄漏源，正好是我们要防的事。
#
# 所以：真实值只存在你本地这个被忽略的文件里，钩子脚本（scripts/pre-commit.sh）
# 是通用且可共享的，两者分离。
#
# ---------------------------------------------------------------------------
# 格式
# ---------------------------------------------------------------------------
# 每行一条规则，`#` 开头的行忽略。
#
#   名称=正则        ← 推荐：报错时会显示名称，容易定位
#   正则             ← 也可以，名称会显示为「站点专属信息」
#
# 正则是 POSIX 扩展正则（grep -E），注意转义点号。
#
# ---------------------------------------------------------------------------
# 建议至少包含以下几类
# ---------------------------------------------------------------------------

# 1. 你自己的域名（含内部测试域名 —— 内部域名同样不该进仓库，
#    因为它会暴露你的基础设施命名，且在仓库转公开时会成为公开信息）
# 测试域名=my-internal-domain\.example

# 2. 服务器公网 IP 与内网网段
# 服务器IP=203\.0\.113\.7
# 内网网段=10\.0\.0\.

# 3. 主机名 / ssh 别名
# 主机名=my-server-hostname

# 4. 内部系统地址
# 内部面板=panel\.example\.internal

# 5. 你所在组织/个人的其他标识（按需）
# 组织标识=my-org-slug

# ---------------------------------------------------------------------------
# 注意
# ---------------------------------------------------------------------------
# · 不要把真实值写进**这个示例文件**——它会被提交。写在 sensitive-patterns.txt 里。
# · 规则越精确越好。过于宽泛的规则（比如单个常见单词）会频繁误报，
#   最终导致大家习惯性使用 --no-verify，反而失去保护作用。
# · 通用凭据格式（sk-… / ghp_… / AWS Key / 私钥块）由钩子和 CI 内置处理，
#   不需要在这里重复。
