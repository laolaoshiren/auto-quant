# 界面布局规范

**本文档是布局的契约。** 配色与字号见 [`DESIGN.md`](DESIGN.md) 与 [`tailwind.config.js`](tailwind.config.js)。

---

## 0. 参考结构

布局参照操作者指定的产品（Vergex）。**核心是「顶部导航 + 两栏内容」**，
不是「左侧导航 + 指标栏 + 主内容」。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 顶部横条：品牌 | 导航链接 ×N | ……… | 状态 | 搜索 | 操作员            │  h-14
├────────────────────────────────────┬─────────────────────────────────┤
│ 主内容区（约 60%）                  │ 侧栏（约 40%）                  │
│                                    │                                 │
│ ▸ 对象选择器 / 标题 + 操作          │ ▸ 侧栏区块标题 + 操作            │
│ ┌──────┬──────┬──────┬──────────┐  │ ┌─────────────────────────────┐ │
│ │指标  │指标  │指标  │指标      │  │ │                             │ │
│ └──────┴──────┴──────┴──────────┘  │ │  独立滚动，撑满整屏高        │ │
│                                    │ │                             │ │
│ ▸ 图表区（最大的一块）              │ │                             │ │
│ ┌────────────────────────────────┐ │ │                             │ │
│ └────────────────────────────────┘ │ └─────────────────────────────┘ │
│                                    │                                 │
│ ▸ 表格区（标签页切换）              │                                 │
│ ┌────────────────────────────────┐ │                                 │
│ └────────────────────────────────┘ │                                 │
└────────────────────────────────────┴─────────────────────────────────┘
```

### 三条硬规则

**1. 导航在顶部，不在左侧。**
左侧导航要吃掉 224px 的**每一个页面**的横向空间。顶部导航把这段空间还给内容。
不再有折叠/展开状态，也不需要记在 localStorage 里。

**2. 一个页面最多两栏，右侧一栏是"伴随信息"。**
左侧放主体（指标、图表、表格），右侧放**可以独立滚动**的伴随内容
（机器人的决策流、详情页的推理全文）。

不是所有页面都需要右栏 —— 列表页（机器人列表、策略列表、行情）就是**整宽一张表**。

**3. 指标是横排卡片，不是竖排指标栏。**
4 个以内的指标横排成一行；超过 4 个再分成两行。不要竖着堆一列 ——
竖排会让每个指标占掉一整行的宽度，而它们的数值都很短。

---

## 1. 顶部导航

- 高度 `h-14`，一条底边线，**不透明背景**（不要 `backdrop-blur`，理由见 §4）。
- 顺序：品牌 → 导航链接 → 弹性空白 → 状态区 → 搜索 → 操作员。
- 导航链接：当前项用**文字变亮 + 底部一条 2px 强调线**表示，
  不要用大面积背景块（顶部横条上会很重）。
- 窄屏（`< lg`）：导航链接收进一个汉堡菜单的抽屉里；品牌与状态保留。
- 快捷键提示（`⌘K`）保留。

---

## 2. 两栏

- `xl` 及以上：`grid-cols-[minmax(0,3fr)_minmax(0,2fr)]`（约 60/40）。
- `xl` 以下：单列堆叠，右栏落到主内容下面。
- 右栏**自己滚动**（`overflow-y-auto`），高度撑满可视区减去顶栏 ——
  决策流有几十条，不该把整页撑长。
- 主内容区**不设最大宽度**：宽屏上把空间给图表和表格，不要留白边。

---

## 3. 主内容区的内部顺序

按"操作者最想知道什么"排：

1. **对象头**：名称、状态、关键操作（启动/停止/配置）
2. **指标行**：4 个以内的关键数字，横排
3. **图表**：最大的一块，但**只在有数据可看时才占大块**（见 §5）
4. **表格**：标签页切换（持仓 / 委托 / 成交 / 订单）

---

## 4. 常驻的 `backdrop-filter` 一律不用

**这条是踩过坑的。** 顶栏曾用 `bg-base-900/80 backdrop-blur`，结果在部分
GPU 驱动、远程桌面与虚拟显示环境下，Chrome 会创建"背景根"并把**整页内容
错误地提升进滤镜图层一起栅格化** —— 表现为整页均匀发虚、但布局完全正常。

毛玻璃在深色界面上几乎看不出来，代价却是这个渲染风险 + 每帧一次合成。
**顶栏、侧栏、sticky 工具条一律用不透明背景。**

对话框与通知的模糊**保留** —— 它们只在打开时存在。

---

## 5. 只显示状态，不显示内部指标

内部指标（时钟偏移、API 权重、快照数量、token 明细、本机时刻）**默认不出现**。

- **越界时才显示**，并且带**后果**而不是原始数值：
  `⚠ 时钟偏差 2.4s`（悬停说明会导致 `-1021`）比 `时钟 +2400 ms` 有用。
- 需要常驻诊断的场景（交易所诊断页）放在**专门的区块**里，不要混进状态区。

> 教训：顶栏曾常驻 `时钟 +22 ms` 与 `权重 59/2,400`。它们在正常运行时永远
> "没事"，看一百次有九十九次拿不到信息（操作者原话："似乎毫无意义"）。

---

## 6. 网格里装卡片必须加 `items-start`

CSS Grid 默认 `align-items: stretch`，**同一行的卡片会被撑成等高**。
一张只有标题的卡会被拉到和旁边写满内容的卡一样高，中间留下一大片空白 ——
看起来就是"卡片错位"。

**这不是美化，是修正**：拉伸不产生任何分组价值，只产生空白。

---

## 7. 文字说的必须是事实

比对齐更严重的问题：**界面上写的话不成立**。

- 机器人停止时不要写「未连接交易所」—— 凭证是好的，只是没有实时读数。
- 没有成交记录时不要显示 `胜率 0.0%` —— 那会让人以为策略很烂，
  实际是它一次都没开过仓。应该说「尚无已平仓交易」。

**机器码（`stopped`、`open_long`、`EXPIRED`…）不得直接显示**，
一律走 `@aq/shared` 里的标签映射（`traderStatusLabel` / `actionLabel` /
`orderStatusLabel` / `orderPurposeLabel` / `orderTypeLabel` / `userRoleLabel` /
`closeReasonLabel`）。存储值不动，只改显示。

## 8. 检查清单

- [ ] 导航在顶部，左侧没有导航栏
- [ ] 需要右栏的页面右栏**独立滚动**且撑满屏高
- [ ] 指标横排，不超过 4 个一行
- [ ] 页面里没有任何常驻的 `backdrop-filter`
- [ ] 没有任何内部诊断值出现在状态区
- [ ] 装卡片的网格都有 `items-start`
- [ ] 每一条界面文案都成立（读一遍，问"这句话是真的吗"）
- [ ] `lg` 及以下正确塌成单列，不出现横向滚动
- [ ] 100% / 125% / 150% 缩放均无横向滚动
