# 前端设计规范

本文档定义界面的**视觉与交互标准**。改动 `packages/web` 下的任何界面代码前先读它。

设计令牌的实际取值在 [`tailwind.config.js`](tailwind.config.js)，本文档解释**为什么**是那些值、以及**怎么用**。

---

## 1. 设计目标

按优先级排列，冲突时上面的赢：

1. **信息优先** —— 这是盯盘与操作的界面。任何装饰如果挤压了数据，就是错的
2. **一眼能懂** —— 用户不该思考"这个数字是什么意思"。层级、单位、颜色要自解释
3. **少动鼠标** —— 能键盘完成的事不要逼用户去点。高频操作要有快捷键
4. **不累眼** —— 用户会长时间盯着它。低对比度、大面积纯色、跳动的动画都会消耗注意力
5. **顺滑** —— 不卡顿、不闪烁、不跳版

## 2. 颜色

### 只用语义色，不写死色值

```tsx
// ✅ 对
<div className="bg-base-900 text-ink-mid border-base-750" />
<div className="text-up" />        // 盈利
<div className="text-down" />      // 亏损

// ❌ 错 —— 写死色值会在换主题时全部失效，而且很容易和语义色不一致
<div className="bg-[#11151e] text-[#a9b4c7]" />
```

### 层级（elevation）

深色界面靠**底色差 + 细边框**分层，不靠阴影。

| 令牌 | 用途 |
| --- | --- |
| `base-950` | 页面底色。全屏只有这一层 |
| `base-900` | 面板（`.panel` 的默认底色） |
| `base-850` | 抬升：表头、输入框、hover 态 |
| `base-800` | 更深一档的交互态 |
| `base-750` / `700` / `600` | 边框：弱 / 常规 / 强调 |

**规则**：子元素的底色必须比父元素**更亮**（数字更小）。反过来会让层次读起来是"凹进去"的。

### 文字

| 令牌 | 用途 |
| --- | --- |
| `ink-strong` | **纯白**。只给关键数字（当前盈亏、权益）。一屏最多几处 |
| `ink-hi` | 正文、主要信息。默认就是它 |
| `ink-mid` | 次要信息：表格单元格、说明 |
| `ink-lo` | 标签、字段名、表头 |
| `ink-faint` | 占位符、禁用 |

不要用 `ink-strong` 写大段文字 —— 纯白在深底上会"发光"，读久了刺眼。

### 交易语义色

| 令牌 | 含义 |
| --- | --- |
| `up` | 涨 / 多 / 盈利 |
| `down` | 跌 / 空 / 亏损 |
| `warn` | 警告：风控触发、降级运行 |
| `accent` | 主操作、可点击、当前选中 |

**关键**：红绿是行业惯例，**不要**为了"好看"改色相。同时两者明度不同，红绿色盲用户靠明暗也能区分。

**盈亏永远要带正负号**，不能只靠颜色 —— 颜色不是所有人都能分辨的。

## 3. 排版

字号基线 **14px**（`text-md`）。最小的辅助字号是 **11px**（`text-xs`），不要再小。

| 类 | 用途 |
| --- | --- |
| `text-4xl` | 首屏唯一的核心数字 |
| `text-3xl` | 关键指标（权益、今日盈亏） |
| `text-2xl` | 卡片数值 |
| `text-xl` | 区块标题 |
| `text-md` | **正文默认**，不写就是它 |
| `text-base` | 次级正文、表格单元格 |
| `text-sm` | 密集表格 |
| `text-xs` | 标签、单位、角标 |

### 数字必须用 `.num`

```tsx
<span className="num text-2xl text-up">+1,234.56</span>
```

`.num` = 等宽 + `tabular-nums`。**没有它，数字列会随数值变化左右抖动**，盯盘时非常难受。

**同时**：数字右对齐（`text-right`），列才能对齐。

## 4. 间距与布局

4px 基准（Tailwind 默认刻度）。常用：`gap-2`(8) `gap-3`(12) `gap-4`(16) `p-4`(16) `p-5`(20)。

### 比例：重点大，次要小

这是用户明确要求的，也是这个界面最容易做错的地方。

```
┌──────────────────────────────────────────────────────┐
│  顶栏：账户状态 · 全局操作 · 搜索(⌘K)        高 56px  │
├────────┬─────────────────────────────────────────────┤
│        │  ┌───────────────────────────────────────┐  │
│ 侧栏   │  │  核心指标区（大、留白足）              │  │
│        │  │  权益 · 今日盈亏 · 胜率 · 持仓        │  │
│ 224px  │  └───────────────────────────────────────┘  │
│        │  ┌──────────────────────┬────────────────┐  │
│ 可折叠 │  │  主内容（图表/表格）  │  次要信息栏    │  │
│ 到 64px│  │  flex-1              │  320–380px     │  │
│        │  └──────────────────────┴────────────────┘  │
└────────┴─────────────────────────────────────────────┘
```

- **核心指标**：`text-3xl`，整行铺开，数字最大
- **主内容**：占剩余宽度，高度给足
- **次要信息**：目标形态是固定窄栏，但**当前实现还没有采用两列布局** ——
  代码里 `xl:w-80` / `2xl:w-96` **零使用**，各页面是单列（`max-w-[110rem]` 居中，
  指标用响应式网格，如 `xl:grid-cols-5`）。唯一固定窄栏是 `Toaster` 的 `w-80`（320px）。
  上面的示意图是**目标**，不是现状；真要改成两列时再回来把这里和示意图一起改。

不要把所有东西做成一样大 —— 那样等于没有重点。

### 响应式

断点用 **em** 而不是 px（见 `tailwind.config.js`），这样浏览器缩放到 150% 时布局会跟着文字一起调整，而不是把内容挤扁。

| 断点 | 布局 |
| --- | --- |
| `< md` | 侧栏收成抽屉，主内容单列，次要信息移到主内容下方 |
| `md`–`lg` | 侧栏图标态（64px），主内容单列 |
| `lg`–`2xl` | 侧栏展开，主内容 + 次要栏两列 |
| `≥ 3xl` | 主内容可以三列，利用超宽屏 |

**必须测的缩放**：100% / 125% / 150%。150% 下不能出现横向滚动条或文字被截断。

## 5. 组件

基础组件在 [`src/components/ui.tsx`](src/components/ui.tsx)。**新页面一律用它们，不要重写。**

| 组件 | 说明 |
| --- | --- |
| `Panel` | 标准容器。`title` + 右上角 `actions` |
| `Button` | 变体 `primary` / `ghost` / `danger` / `success` / `warn`，尺寸 `sm` |
| `Badge` | 状态标签，`tone` 决定颜色 |
| `Dot` | 状态圆点，`pulse` 表示进行中 |
| `Stat` | 指标卡：label + 大数值 + 可选变化量 |
| `Field` | 表单字段包装：label + hint + error |
| `TextInput` / `NumberInput` / `Select` / `TextArea` / `Toggle` | 表单控件（基于 Radix，含无障碍支持） |
| `Modal` | 对话框（Radix Dialog：焦点陷阱、Esc、点击遮罩关闭都正确） |
| `Collapsible` | 折叠区（Radix，带正确的高度动画与 aria） |
| `Empty` | 空状态 |
| `ErrorNote` | 错误提示 |
| `KV` | 键值对行 |
| `CopyButton` | 复制按钮，带"已复制"反馈 |

### 用 Radix，不要手写

对话框、下拉、选项卡、提示气泡这类东西**手写必然有边界问题**：焦点陷阱、Esc 关闭、滚动锁定、屏幕阅读器、点击外部。用 Radix 原语（`@radix-ui/react-*`），只负责外观。

图标用 [`lucide-react`](https://lucide.dev)，**不要**再用文字符号当图标。

## 6. 交互

### 少动鼠标

- **命令面板（⌘K / Ctrl+K）**：跳页面、切机器人、开关操作。这是减少鼠标操作最有效的一招
- **快捷键**：`⌘K` 命令面板、`Esc` 关闭浮层、`/` 聚焦搜索、`g` 后接字母跳页
- **表格行**：整行可点，不要只让一个小图标可点
- **表单**：`Enter` 提交、`Esc` 取消，输入框自动聚焦

### 反馈

- 任何**超过 300ms** 的操作都要有加载态，否则用户会以为卡死了
- 危险操作（启动实盘、删除机器人）要二次确认，确认文案里写清**后果**
- 成功/失败用 toast（自研的 `components/Toaster.tsx`，读 `useEvents` 的 `toasts`；
  **不是** `sonner`），不要把用户从当前上下文拽走

### 不要卡顿

- **表格超过 100 行就不要全量渲染** —— 分页或虚拟滚动
- **列表项用稳定的 `key`**，不要用数组下标
- **高频更新的数值**（实时盈亏）不要触发整棵树重渲染
- 路由级**代码分割**，首屏不要把所有页面打进来

## 7. 文案

界面语言是**简体中文**。机器契约（字段名、状态码）保持英文。

- 说人话：「读取行情失败，正在重试」而不是「Error: fetch failed」
- **带上具体数字**：「杠杆已从 20x 压到上限 5x」而不是「杠杆超限」
- 空状态要给出**下一步做什么**，而不只是「暂无数据」
- 单位写进标签：「仓位（USDT）」而不是靠用户猜

## 8. 自查清单

提交界面前逐条过：

- [ ] 没有写死的色值，全部用语义令牌
- [ ] 所有数字用了 `.num` 且右对齐
- [ ] 核心指标明显比次要信息大
- [ ] 100% / 125% / 150% 缩放下都不出现横向滚动条
- [ ] 窄屏（< 768px）下布局不塌
- [ ] 键盘能走完主要流程，焦点看得见
- [ ] 加载 / 空 / 错误三种状态都有
- [ ] 没有超过 100 行的表格全量渲染
- [ ] 控制台无报错、无 key 警告
