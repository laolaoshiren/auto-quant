# 方案：调整止盈 / 止损

**状态：待评审，未实现。**

---

## 1. 要解决什么

现在一旦开仓，止损位和止盈位就**固定了**。一笔已经浮盈的仓位，**没有任何办法把止损上移**。

这是交易员最基本的风控动作——"把止损移到保本"能把一笔有浮盈的交易变成**不可能亏损**。系统现在做不到，所以：

- 浮盈无法锁定，只能等止盈或等回撤
- 趋势走出来之后，止损还在原地，一次回撤就吃掉全部浮盈

---

## 2. 新增动作

沿用现有命名约定（`open_long` / `close_long`）：

| 动作 | 含义 |
| --- | --- |
| `adjust_long` | 调整**多头**仓位的保护单 |
| `adjust_short` | 调整**空头**仓位的保护单 |

解析器已经会校验「平仓动作必须对应真实存在且方向相符的仓位」（`parser.ts:352`），
调整动作复用同一条校验。

**保持方向前缀的理由**：方向不符的调整请求和方向不符的平仓请求一样危险，
用同一条已有校验拦住它，比新写一套更可靠。

---

## 3. 两个必须守住的不变量

### 不变量一：止损只能朝**降低风险**的方向移动

| 仓位 | 允许 | 拒绝 |
| --- | --- | --- |
| 多头 | 止损**上移** | 止损下移 |
| 空头 | 止损**下移** | 止损上移 |

**这是一条单向棘轮：止损只能前进，不能后退。**

为什么必须这样：模型最自然的错误行为就是"行情快打到止损了，把止损挪远一点"——
**这正是让账户爆掉的行为**。允许它等于把风控交给一个会犯这个错的组件。

这条规则的好处是**简单到可以一眼验证**：新止损必须严格比旧止损更靠近当前价。
没有例外、没有"特殊情况下可以放宽"。

### 不变量二：调整后的**剩余盈亏比**不得低于配置下限

对已持仓的仓位，剩余风险与剩余回报按**当前价**算：

```
剩余风险 = |当前价 − 止损|
剩余回报 = |止盈 − 当前价|
剩余盈亏比 = 剩余回报 ÷ 剩余风险
```

要求 `剩余盈亏比 ≥ riskControl.minRiskRewardRatio`。

为什么需要这一条：单靠不变量一还不够。模型可以把止盈推到很远、止损贴着当前价，
造出一个"看起来风险很小但盈亏比极差"的仓位，然后一直挂在那里。
不变量二防止仓位**衰减成一个坏赌注**。

---

## 4. 执行顺序 —— ⚠️ 这里有一个我不替你决定的风险

调整止损 = **撤掉旧的条件单，挂一张新的**。两步之间仓位是**没有保护**的。
顺序只有两种，各有各的风险：

### 方案 A：先撤旧，再挂新

- **风险**：撤掉之后挂不上 → 仓位在一段时间内**完全没有止损**
- **兜底**：挂不上就立刻重试一次；仍失败则**立即市价平仓**（沿用 §2.6 已有的
  `protection_unavailable` 路径）
- 最坏结果：**提前离场**（安全，只是少赚）

### 方案 B：先挂新，再撤旧

- **风险**：两张 `closePosition=true` 的条件单**同时存活**。这正是 AGENTS.md §2.7
  记录的坑——「`closePosition=true` 的条件单在手动平仓后依然存活，**会朝反方向开出新仓**」
- 最坏结果：**反向开出一个没有保护的新仓位**（危险，与 §2.6 的意图相反）

### 我的建议：**方案 A**

理由：方案 A 的最坏结果是"提前离场"，方案 B 的最坏结果是"反向裸仓"。
**爆仓风险不对称**，所以选 A。

而且 A 的兜底逻辑（挂不上就平仓）**代码已经存在** —— `executeOpen` 里就是这么做的，
复用它而不是新写一套。

**但这是我的判断，不是事实。** 如果你更希望避免"提前离场"，B 也有它的道理。

## 5. 风控要改什么

| 位置 | 改动 |
| --- | --- |
| `ActionPriority`（`risk/engine.ts`） | 调整动作归入**降低风险**一类，排序在开仓**之前**（§2.9） |
| 新增 `reviewAdjust()` | 校验上面两个不变量，**每次拒绝或钳制都要写进 `adjustments` / `reason`，并带具体数字** |
| 保护单存在性 | 调整前必须确认旧单真实存在；不存在则按 §2.6 处理（补挂或平仓），**不做"调整"** |
| 名义价值 / 保证金 | **不重新计算** —— 调整不改变仓位大小，敞口不变 |

**明确不做的事**：调整动作**不能**改变数量、杠杆、保证金模式。那是加仓/减仓，
是另一个方案，需要重新设计风控（同一标的多仓位的保证金与止损归属都要重算）。

## 6. 模型怎么表达

提示词的 `action` 取值增加两个，并新增一段说明：

- 调整时**必须**给出 `stop_loss`，可选的 `take_profit`
- **明确告诉模型止损只能收紧**。不说的话它会尝试放宽，然后被风控拒绝——
  每个周期浪费一次调用
- 持仓上下文里要显示**当前的止损/止盈**，否则模型不知道要调整什么

**需要先确认**：现在的提示词里，持仓信息是否包含当前止损/止盈？如果不包含，
这是一个必须先补的前置改动。

## 8. 测试（§3.5：每条注释写明它防的是什么 bug）

| 测试 | 防的是什么 |
| --- | --- |
| 多头止损下移 → 拒绝 | **模型试图躲开止损**——最危险的行为 |
| 空头止损上移 → 拒绝 | 同上，反方向 |
| 多头止损上移 → 通过 | 确认规则不是"一律拒绝" |
| 调整后剩余盈亏比低于下限 → 拒绝 | 仓位衰减成坏赌注 |
| 调整不存在的仓位 → 拒绝并说明 | 方向/存在性校验 |
| 挂新单失败 → 走 `protection_unavailable` 平仓 | 仓位不会裸露 |
| 调整后数量/杠杆**未变** | 防止误改成加仓 |
| 提示词包含当前止损止盈 | 模型知道要调整什么 |

## 10. 需要你决定的两件事

1. **执行顺序选 A 还是 B**（我建议 A，见 §4）
2. **止盈是否也套用"只能朝降低风险方向"**：止损必须是单向棘轮；
   止盈我倾向**允许双向**（拉近锁定利润、拉远争取大波段都不直接增加风险），
   由不变量二兜住。但如果你希望更保守，也可以让止盈同样单向。
