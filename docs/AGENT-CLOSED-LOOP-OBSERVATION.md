## 二、★ AI 的复盘直接指出了我实现里的一个真缺口

它的原话：

> **数据不足**，无法判定这笔 SOLUSDT 的盈亏归因：唯一已知的是由 `drawdown_guard`
> 触发平仓、净 +0.0021（约等于打平），**没有入场依据、方向、周期、持仓时间和浮盈回撤轨迹**，
> 因此无法区分是"正常波动下的保护性离场"还是"止盈过晚导致利润回吐"；
> 可复用的只有一点 —— **回撤保护触发时净利已接近零，说明该出场规则是在回吐后才被动执行**，
> 若后续记录显示曾有可观浮盈，则应检讨止盈/移动止损设置。

**它是对的，而且它说的正是我代码的问题。**

`reviewClosedTrade()` 目前只收到四个字段：

```ts
{ tradeId, symbol, closeReason, netPnl }
```

**而它需要的事实大部分在库里、只是没传给它**：

| 它想要的 | 哪里能找到 |
| --- | --- |
| 入场依据 / 方向 / 周期 | `decision_records.raw_response`（那一轮模型的完整推理） |
| 持仓时长 | `trades.hold_minutes`（**已经落库了，只是没传**） |
| **浮盈回撤轨迹** | `positions.peak_pnl_percent`（**判断"止盈是否设晚"的唯一依据**） |
| 手续费占比 | `trades.fee`（已落库） |

**"浮盈峰值"这一条尤其要紧**：它的推理链是
"回撤保护触发时净利接近零 → 若曾有可观浮盈，则应检讨止盈/移动止损" ——
**而这个前提它拿不到，于是只能把结论卡在"数据不足"。**

**让 AI 说"数据不足"是我的责任，不是它的。**

## 三、第二个事实：手续费吃掉了毛利的 77%

```
毛 +0.0091   手续费 0.0070   净 +0.0021
→ 手续费占比 77%
```

这正是监控期那个病的复现：**毛赚一点点，手续费拿走大半。**

**而这也解释了保本止损为什么没触发**：它是 8%，而 3x 杠杆下要价格动约 2.7%；
这笔在 71 分钟内从没到过那个幅度，就先回落到被回撤守卫平掉了。

**`breakevenTriggerPercent = 8` 对当前波动很可能设得太高** ——
**而这正是一个该由 AI 用数据去调的参数**（它现在知道了这个旋钮的存在）。
在它拿到"浮盈回撤轨迹"之前，它没法判断该调成多少 —— **这又回到第二节的缺口。**
