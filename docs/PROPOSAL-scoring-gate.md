# 提案：从"数据 dump"回到"先算分、再看图"

**状态**：待实施
**来源**：用户自己的干净室项目（`vergex-clone`，README 明写「只借鉴策略思想，不复制任何代码」）

---

## 0. 这份提案要纠正的是我自己的一个设计失衡

监控期实测：**单次决策 58,266 tokens、延迟 48 秒、每小时 270 万 tokens**，
而那个策略**扣费前毛盈亏 ≈ 0**。

用户自己的干净室实现是**另一个极端**：

| | 用户的干净室 | 我的实现 |
| --- | --- | --- |
| 单次决策提示词 | **约 200 tokens** | **58,266 tokens** |
| 候选处理 | 先算评分，**不到 75 分不给模型看** | 11 个候选的完整指标全丢给模型 |
| 提示词形态 | **门控规则（4 条）+ 一行上下文** | 大段数据 dump |
| 决策粒度 | 每次一个标的 | 一次看 11 个 |

**两个都极端，但值得认真对待的是这个对比揭示的问题**：

> **我假设"给模型更多数据 = 更好的判断"。而实测并没有支持这个假设 ——
> 那个给得最多的版本扣费前没有优势。**

**更省的解释**：信号淹没在 5.8 万 token 里，本身就会让判断变差，
不只是变贵。**"多看"和"看得准"不是一回事。**

## 1. 要采纳的四条

### 1.1 前置评分：先决定"看什么"，再花 token

用户的做法：`scoring.py` 算一个 0–100 的复合分，**≥75 才进提示词**。

**四个分量，其中一个是减分**：

| 分量 | 看什么 |
| --- | --- |
| 趋势分 | 4h 方向 |
| 突破量能分 | 15m 放量突破 |
| 整理分 | 15m 窄幅整理（蓄势） |
| **波动率惩罚** | 波动过大**扣分** |

**"有减分项"这一点比加分项更重要**：它把"什么样的行情**不该做**"写成了可检验的规则，
而不是留给模型在一堆指标里自己权衡。

**我要做的**：把这套评分做成本项目里的一个纯函数（`scoreSymbol()`），
**在选币之后、构建提示词之前**跑一遍，只把过线的候选交给模型。

**注意它与现有 `coinSource` 选币的关系**：选币决定"池子里有谁"，
评分决定"这一轮谁值得看"。**两者不是一回事，也不该合并。**

### 1.2 短而规则的提示词

用户的 system prompt 是四条门控规则，**数字全部写死**
（"≥75 分才可开仓"、"4h 收阴线且跌破关键位时止盈"）。

**对比我的提示词**：一大段数据 + 让模型自己权衡。

**规则化的好处是可检验**：它把"我要求它做什么"变成了能对照结果的东西。
**这不是限制模型的智能，而是把确定性高的部分从模型手里拿走** ——
那些部分（"多少分才够"）本来就不该由模型每次重新发明。

**但这一条与「AI 托管」不冲突**：门控规则本身**也是可调参数**，
只是它的形态从"一段散文"变成了"几个数字 + 几条规则"。

### 1.3 `breakeven_trigger`：浮盈到 8% 把止损移到成本价

**这是我系统里没有的机制**，而它恰好治我实测到的病：

> 平均持仓 4.6 分钟、手续费占毛盈亏 38% ——
> **一笔已经赚到钱的单又变回亏损单，是最亏的做法。**

我有回撤守卫和 `peakPnlPercent`，但**没有"够本就走"这条**。

**要做**：在既有持仓管理里加一条 —— 浮盈达到 `breakevenTriggerPercent`
就把止损移到开仓价（**只能往有利方向移，永不反向**，与"止损棘轮单向"同一条不变量）。

### 1.4 严格解析的纪律（已有，且一致）

用户的 `decision.py`：**严格 JSON、解析失败抛错不下单、`action` 白名单**。

**我的 `parser.ts` 是同一套**（§2.4）。**两条独立路径得出同一个结论，说明它是对的** ——
这一条不需要改，只需要记下"我们对齐了"。

## 2. 与「AI 托管」的关系（这一节很重要）

**有人会问：既然评分门槛写死了数字，那 AI 托管还智能在哪？**

**答**：把确定性高的部分变成规则，**恰恰是为了让 AI 的注意力用在真正需要判断的地方**。

| 谁做 | 做什么 |
| --- | --- |
| **代码（确定性）** | 算分、卡门槛、移止损到成本价、风控钳位 |
| **AI（判断）** | **门槛该设多少、评分该看哪些分量、提示词该怎么写、什么行情该停手** |

**换句话说**：评分门槛不是"把 AI 换掉"，而是**给 AI 一个可调、可检验的旋钮**。
现在的做法（把 11 个标的的原始指标全给模型）让 AI 每次都在重新发明"多少分算好" ——
**而那是一个应该被沉淀下来、并且能被实验检验的参数。**

**这也回应了用户的一个观察**：

> 同样的参数、不同的提示词，结果往往不一样。

**所以提示词是一个独立的、值得优化的一维。** 而它要被**单独检验** ——
否则 AI 改了提示词，我们分不清是提示词起了作用还是市场变了。
（这一条要靠 `agent_experiments` 的"改了什么 + 之后真实结果 + 样本量门槛"来保证。）

## 3. 实施顺序

| 阶段 | 内容 | 验证 |
| --- | --- | --- |
| **A** | `scoreSymbol()` 纯函数 + 单元测试（含惩罚项的边界） | 单元测试；**不要**用真实 K 线做断言（会变成市场数据依赖的假测试） |
| **B** | 评分门槛接入选币之后；门槛值进 `StrategyConfig`（有 `.default()`） | `npm run sim` 必须 15/15 |
| **C** | `breakevenTriggerPercent` 进配置 + 持仓管理里实现（单向棘轮） | 单元测试钉住"只往有利方向移" |
| **D** | 提示词精简：把"让模型自己权衡的指标"收进规则 | **提示词 token 数必须显著下降**，且 `npm run sim` 仍 15/15 |
| **E** | 在 AI 托管模式下把门槛值、评分权重、提示词一起交给 AI 调 | 端到端测试扩展 |

**不做的事**：
- **不移植任何外部代码或提示词文本**（干净室红线）
- 不因为"用户的做法更简单"就推翻既有风控层 —— **评分门槛是加在选币之后、风控之前的过滤，不是替代风控**
- 不在未测的情况下声称"提示词更短所以更好" —— **那需要 A/B，见第 4 节**

## 4. 怎么知道这些改动真的有用（而不是"看起来更专业"）

**"提示词更短、门槛更严"听起来都对，但它们是不是真的更好，只能测。**

- **对照**：同样的行情窗口、同样的模型，跑「旧提示词」与「新提示词」两组
  （`npm run sim:live` 支持真实模型；**注意它花钱**）
- **样本量纪律**：**少于 30 笔平仓不下结论**（与 `agent_experiments` 的结算门槛同一条）
- **不能只看净值**：还要看手续费占比与平均持仓时长 ——
  **一个靠减少交易把手续费降下来的改动，和一个真的更会择时的改动，净值可能一样，
  但含义完全不同。**

**我不会在这个提案里写"这样改会更好"** —— 只写"这样改**可以减少浪费**，
而它是否提升盈利能力需要测"。
