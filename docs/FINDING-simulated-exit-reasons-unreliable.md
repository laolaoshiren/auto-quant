# FINDING：模拟盘（dry_run）的平仓原因与成交价**不可信**

> 日期：2026-10-15 · 对象：`#11 [团队测试] 多智能体`（`ai_team`，`dry_run=1`，账户 2）
> 状态：**已定位、未修复**（修法见第 4 节，但需要先决定"模拟盘该怎么平仓"）

---

## 0. 结论摘要

```
模拟盘 #11 的 32 笔平仓里：
  · 保护单【从未成交过】—— stop_loss / take_profit 的 FILLED = 0
  · 31/32 笔的出场价【离所有保护单都 >0.5%】（最远 5.74%）
  ⇒ 所以 close_reason 全部来自 reasonFromPrice 的"离谁近猜谁"
  ⇒ 而那个"最近的"根本不是触发它的单 —— 纯属巧合

后果：stop_loss / take_profit 这两个标签在模拟盘上【没有意义】，
      基于它们做的任何统计（"止损太紧"、"止盈设晚"）都建立在噪声上。
```

⚠️ **同时纠正我自己两次误报**（见第 5 节）：
1. 我报过"开多/空头方向矛盾" —— **是我把两轮日志看成一行的误读**；
2. 我报过"positions 表有 37 行幽灵持仓" —— **那 37 行全是 `status=closed`，UI 显示 0 是对的**。

## 1. 事实（实测）

### 1.1 保护单的状态分布（`orders` 表）

```
purpose        status       笔数
stop_loss      CANCELED      31     ← 没有 FILLED
stop_loss      REJECTED       5
stop_loss      NEW            1
take_profit    CANCELED      31     ← 没有 FILLED
take_profit    NEW            1
entry          FILLED        37
exit           FILLED         5
```

### 1.2 出场价与保护单的距离

```
出场价贴着保护单（≤0.5%）  1 笔
离所有保护单都 >0.5%      31 笔     ← 最远 5.74%（#384 QUSDT）
```

判据：对每一笔，取它**开仓到平仓时间窗内**该标的的全部 `stop_loss`/`take_profit` 单，
算 `|exit_price − stop_price| / entry_price × 100%` 的最小值。

### 1.3 盈亏符号与标签的矛盾

```
标 take_profit 却亏钱：5 笔（#383 #385 #401 #411 #416）
  —— 止盈单在有利方向、且【没有"移动止盈"机制】⇒ 这在逻辑上不可能
标 stop_loss 却赚钱：10 笔
  —— 这在移动止损下是【合法的】（`runtime.ts:326` 已有这条契约：
     止损位被上移到成本之上，触发时就是赚的）
```

⇒ 所以**只有"止盈却亏钱"那 5 笔是硬矛盾**；"止损却赚钱"不能算错。

## 2. 根因链

```
① `simulateAlgo()` 建完单就不管了 —— 保护单永远停在 NEW
   （`broker.ts:1054`，没有价格触发的模拟）

② 而 `getPositions()` 【没有 dryRun 守卫】→ 真去查交易所
   → #11 的成交是本地模拟的，从不真的下单
   → 交易所那边【永远没有它的持仓】→ 返回空

③ 对账发现"仓位消失了"（其实它从没在交易所存在过）
   → `lastFillFor(symbol)` 拿"该标的最后一笔成交价"当 exitPrice
   ⚠️ 而账户 2 上还有 #9 在交易 —— 那可能是【#9 的成交价】

④ `detectCloseReason()`：
   · `getAlgoOrder` 有 dryRun 守卫 → 返回 null → 两个都判不出
   · 于是走 `reasonFromPrice(exitPrice, stopLoss, takeProfit)`
   · 它只比较"离止损近还是离止盈近" —— 【完全不看盈亏方向】
   ⇒ 猜出来的原因
```

⚠️ **第 ③ 步还有一个更严重的含义**：`exit_price` 可能不是 #11 自己的成交价。
实测进出价差从 0.000% 到 0.980% 不等，而那些"贴着保护单"的只有 1 笔 ——
说明这个价更像是**当时的标记价**或**别人的成交价**。

## 3. 影响范围（哪些结论不能用）

```
❌ 不能用：「模拟盘止损太紧」（22 笔 stop_loss 平均持有 4.1 分钟）
   —— 标签本身是猜的，而且"止损但赚钱"有 10 笔
❌ 不能用：「模拟盘胜率 38.9%」做参数调优
   —— 分子分母都建立在猜出来的 close_reason 上
❌ 不能用：模拟盘的单笔盈亏做归因
   —— exit_price 来源可疑

✅ 可以用：模拟盘的**总净额**（-0.0524）
   —— 它是 `net_pnl` 求和，而 net_pnl 来自本地模拟成交，不依赖 close_reason
✅ 可以用：模拟盘的**开仓方向与时机**
   —— 那些是模型决策的直接记录（`decision_records`）
```

## 4. 修法（待定，两条路）

### A. 让模拟盘真的模拟保护单成交（推荐）

`simulateAlgo()` 记下触发价；在每次读持仓/标记价时判断是否触发，
触发就**真的产出一笔模拟成交**并把 `algoStatus` 置为 `FILLED`。

- 好处：`close_reason` 变成**真实推断**（哪张单先触发就是它），
  `exit_price` 变成**触发价**（而不是别处的价）—— 模拟盘才有仿真价值
- 代价：要在 `BinanceBroker` 里加一个"条件单撮合"的状态机

### B. 给模拟盘一个诚实的标签

不模拟成交，但把 `close_reason` 标成 `simulated_exit`，
并在界面/提示词里说明"模拟盘的原因字段不可信"。

- 好处：改动小、不会引入新的假象
- 代价：模拟盘仍然不能用来验证止损/止盈策略

⚠️ **必须选一个** —— 现状最糟：它给出了**看起来可信、实际是噪声**的标签，
而那会污染模型的记忆（`agent_memory` 会把这些"教训"存下来）。

## 5. 我的两次误报（诚实记录）

### 误报 1：「开多 WALUSDT ✓ 已执行 已开仓空头」方向矛盾

**实际数据**（`decision_records` 第 215 轮）：
```
决策: open_short WALUSDT conf=58
日志: action=open_short symbol=WALUSDT status=ok detail=已开仓空头 181 @ 0.06070462
trades: #422 WALUSDT side=short
```
**三者完全一致**。我把**两轮不同的日志**看成了同一行。

⚠️ 教训：截图里相邻的两行属于**不同的周期**，而我把它们当成了一行。
**先查数据再报 BUG** —— 这正是 `docs/AGENTS.md` §3.2 那条纪律。

### 误报 2：「positions 表有 37 行幽灵持仓」

**实际**：那 37 行全是 `status='closed'`（历史行），
而 `positions.open()` 查的是 `status='open'` → **0 行**，UI 显示「当前持仓 0」是对的。

⚠️ 教训：我看到了"37 行"就推断"UI 该显示 37"，
**没有先确认查询条件**。同一个错误在 24 小时内犯了两次。
