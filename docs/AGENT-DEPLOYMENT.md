## 二、启动前的代码审查发现一个**启动死锁**（已修）

部署完成后、启动真钱机器人之前，我复查了一遍判定逻辑，发现一个**没有任何症状**的缺陷：

```
isEnabled()              判据是 agent_config_json 非空
agent_config_json 非空    由 set_params 写入
set_params 被调用         需要 AI 在跑
AI 在跑                  需要 isEnabled() 为真
```

**一个刚建的 AI 机器人会周期照跑、日志干净，但智能体一次都不会被调用。**

修法：判据加上"策略是 `ai_managed` 预设"。选了那个预设就等于"要求 AI 托管"，
哪怕它还没改过任何参数。变异检查：去掉这条分支，对应用例立刻变红。

**这个缺陷值得单独记**：它不报错、不报警、不影响机器人"看起来在运行"，
只能通过**在启动真钱之前把判定逻辑重读一遍**发现。

## 三、启动被预检拦住（**当前阻塞**）

创建了策略 #8（`presetId=ai_managed`，`requireStopLoss=true`、`maxPositions=2`、
`maxEntriesPerHour=2`）与机器人 #8，启动时返回：

```
HTTP 400  AI 模型「基源律动」无法访问：余额不足
```

预检的其余各项**全部通过**：

| 检查项 | 结果 |
| --- | --- |
| 账户访问 | ✅ 权益 9.11 USDT，可用 9.11 USDT |
| 交易余额 | ✅ 可用余额 9.11 USDT |
| API Key 权限 | ✅ |
| **AI 模型** | ❌ **余额不足** |

**预检拦对了。** 没有这道检查的话，机器人会启动、每个周期都失败，
而账户在无人决策的状态下空转 —— 操作者从状态上看不出区别。

**这是只有账户所有者能解决的阻塞**：需要给模型服务商充值，或换一个可用的模型。
