## 1. 两个口径给出的答案相反

```
平台账本（trades 表汇总）：净 +5.6573  →  +5.65%    ← 看起来在赚钱
交易所流水（平台自算）：    净 -6.9563  →  -6.95%    ← 实际在亏
差额：12.6135 USDT（相对 100 USDT 本金是 12.6%）
```

**两者相差 12.6 个百分点 —— 这个量级足以让"策略有效"与"策略无效"的结论完全相反。**

⚠️ 这两个数都来自 `settings` 表的 `ledger_check:10`（平台自己算的），
不是我手算的：
```json

`foreignNet: 0` 说明**没有外来交易的干扰** —— 差额是平台自己记出来的。

## 3. 这一类是什么：方向不可信、金额来自流水

代码在 `autoTrader.ts:6348`。它的注释（`6276-6281`）写着：

> 「**开/平方向、数量与价位都不可信**，但净额仍按交易所口径记账。
>  这通常说明成交历史的窗口起点落在持仓中间，净头寸法把开/平判反了。」

而金额取的是交易所流水（`realizedInWindow`），**不是**重建的推测 —— 那部分设计是对的。

### ⚠️ 但它留下了 `entry_price` / `exit_price` / `side` 三个**不可信**的字段

实测那 38 笔里，**16 笔的"价格方向"与"盈亏符号"自相矛盾**：

```

**对照**：`stop_loss` 的 45 笔**全部自洽**（0 笔矛盾）。

⇒ 所以矛盾**只出现在这一类**，而且与它的注释一致（"方向不可信"）。
**金额是对的（来自流水），价格与方向是错的。**

## 4. 为什么这仍然是个真问题

```
① 任何按 side/entry/exit 重算的消费者都会算错
   —— 例如 `reasonFromPrice`、胜率统计、归因分析
② 更严重的是：它让【账本】与【交易所】对不上 12.6
   —— 而"账本可信"是这套系统一切结论的前提
③ 我在排查过程中被它误导过一次：
   一度以为"take_profit 却在亏损"是执行 BUG，真实原因是
   这一类记录的价格字段不可信
```

⚠️ **重复记账的嫌疑已排除**：按 `symbol + closed_at` 去重，38 笔**没有重复行**。
所以差额不是"同一笔记了两遍"，而是**别的来源**（尚未定位）。

## 6. 顺带纠正：`#11` 团队模式的成绩**不能用来评价策略**

```
#11 是 dry_run = 1（模拟盘）
31 笔成交，而【保护单 FILLED = 0 张】—— 从没有一张止损/止盈真触发过
26 笔的平仓【没有对应的平仓订单】（exit FILLED 只有 5 张）
⇒ 那 26 笔是"对账时发现仓位不在了 → 推断为已平仓"
⇒ close_reason 由 `reasonFromPrice` 【猜】出来
```

所以**我之前说"团队模式 3 天净亏 0.044"不准确** —— 那个数字来自模拟盘的推断记录。
