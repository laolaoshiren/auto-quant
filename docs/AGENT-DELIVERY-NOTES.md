## 1. 为什么它之前 60 多个周期一笔都不开 —— 四个叠加的原因

**这一节是本文档的重点。四个原因里有三个是配置/设计问题，一个是我的错误。**

### ① `minPositionSize` 高于账户能承受的名义价值（算术不可能）

```
minPositionSize: 12  而  9.11 USDT × 50% 保证金 ÷ 2x 杠杆 = 9.1 USDT 名义上限
→ 任何仓位都不成立
```

**AI 自己诊断出并修了它**（实验 #1：12 → 6）。

### ② 山寨币名义上限低于交易所下限（算术不可能）

```
9.11 × altcoinMaxPositionValueRatio(0.5) = 4.55 USDT
币安合约最小名义价值 ≈ 5 USDT
→ 山寨币永远开不了仓
```

**AI 又自己诊断出并修了它**（实验 #2：0.5 → 1.0，
它的理由是"合法区间仅 [5, 5.47]，余量约 9%"）。

**这两条能自愈，是因为我加了「长期零成交」触发判据** ——
在那之前，所有既有判据都是 0（无成交、无被拒、权益不动），
只有 60 分钟兜底会唤醒它，而醒来看到的是同一份数据。

### ③ 入场标准是"人类稳健交易员"的规则 ← **根本性的设计错误**

模型每轮的原话：

> 没有任何一个标的能拿出**多条相互独立、方向一致的确认**……
> 按稳健模式原则：信号冲突时正确动作是等待。

**"入场前至少需要三个相互独立的确认、拒绝'有可能'的机会、只接受'显而易见'的机会"** ——
在震荡市里那等于永远不开单。

**而 AI 托管这个模式的全部意义就是"由 AI 适应"。继承一份最保守的人类规则是自相矛盾。**

**修法**：把入场标准改成"三个可检验条件"（有可辨认的失效位、盈亏比 ≥1.5、
不与大周期冲突），并明确 **"连续多个周期不开单本身是一个需要解释的状态"**。

### ④ 我自己加的评分门槛在主动造成伤害

我加了候选评分门槛，第一次选 `minScore: 25`（**没算过打分函数的量纲，
把所有候选滤空了**），降到 10 之后——

**它把 BTC/ETH 滤掉了，留下的是超买山寨币。**

| 标的 | 我的趋势分 | 结果 |
| --- | --- | --- |
| BTC（4H 偏空） | 负 × 40 → 钳到 0 | **被滤掉** |
| ZEC（24h +17%） | 满分 → +40 | **入选** |

**而模型接着正确地拒绝了 ZEC**（"4H RSI 85，抛物线末端的追高"）。

**所以门槛做了两件坏事**：滤掉唯一能交易的标的（BTC/ETH），
留下模型一定会拒绝的超买山寨币。**我把它关掉了。**

**它的设计缺陷**：`trend` 分量把"下行"算作负贡献，于是系统性偏好已经涨很多的币；
而"已经涨很多"恰恰是坏入场。**要修的是评分函数本身**，不是门槛值。

## 2. 修掉的两个静默缺陷

### 模型的原生工具调用格式没被接住（在烧钱）

```
#2  failed  6 步  25621/4725 tokens
    模型连续两轮没有输出可解析的工具调用
```

Command 厂商的模型用它训练时的原生格式回来（类 XML，分隔符是全角竖线包 DSML），
而解析器只认 JSON。**看起来像模型不听话，实际是"我们没接住它的话"。**

修复后同一路径：`#3 ok`。**只多认格式，不放宽语义**（幻觉工具名在两种方言下都被拒）。

### 实验记录里的 `tool_calls` 一直是空的

**而同一个文件里我写着**"用一个引用盒子把当前步骤快照进去" —— **那句话是错的**：
闭包返回引用，而赋值在循环结束之后。**每条调参实验都丢了推理依据，完全看不出来。**

修法：循环每步实时回调。两处都有变异检查。
