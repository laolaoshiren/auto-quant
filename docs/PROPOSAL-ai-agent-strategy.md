# 提案：全自动智能托管策略（AI Agent 模式）

**状态**：待确认
**目标**：把「定时问模型 → 按固定参数下单」升级为「给 AI 一个盈利目标，它自己定参数、自己调整、自己反思」。

---

## 0. 先说一件必须说清楚的事

你要的是「**越跑越厉害，盈利最大化**」。这个方向可以做，但有两件事我必须先摆在前面，
否则做出来的东西会让你**误判它的能力**：

**① 「反思」本身不会让它变强。** 让模型"回顾一下最近的交易并改进"，
它会生成一段听起来很专业的文字，**而那与它是否真的找到了规律无关**。
真正让它变强的只有一个东西：**把"我在什么情况下改了什么 → 之后真实发生了什么"
作为事实喂回去**。所以这个设计里，"学习"不是一句提示词，而是**一张落库的实验记录表**。

**② 小样本会说谎。** 20 笔交易无法区分"策略有效"和"运气好"。
一个只看最近 10 笔就敢加杠杆的智能体，**会在它学会之前先把账户做没**。
所以硬上限（第 3 节）不是保守，是**让它活得够久以学到东西**。

**结论**：我会把「可累积、可审计、有依据的自我调整」做扎实。
但**「越跑越厉害」是一个需要被测出来的经验命题，不是实现出来就成立的**。
第 6 节给了测量方式。

## 1. 三层结构：大脑 / 决策 / 风控

```
┌───────────────────────────────────────────────────────────┐
│ ① 大脑（AI Agent）—— 低频，改策略                          │
│   触发：有新的真实结果 / 权益显著变化 / 连亏 / 兜底超时      │
│   输入：绩效、权益轨迹、自己改过什么+之后发生了什么、市场概览  │
│   输出：参数补丁 + 一段可审计的判断理由                      │
│   形式：**工具循环**（模型选工具 → 程序执行 → 结果回喂 → …）  │
├───────────────────────────────────────────────────────────┤
│ ② 决策（每轮）—— 中频，按当前参数选标的与下单               │
│   就是现在的 runCycle，唯一的区别是参数来自大脑而非用户      │
├───────────────────────────────────────────────────────────┤
│ ③ 风控（每次下单）—— **不可越过**                          │
│   现状不变。AI 不能改这里，也不能绕过（§2.1）               │
└───────────────────────────────────────────────────────────┘
```

**为什么必须分三层**：你希望 AI 控制一切，但**有些东西一旦让它自己控制，
一次错误判断就能把账户清零**。三层的作用是让 AI 在**②的层面完全自由**，
在①层面**只能收紧不能放松**。

## 2. 大脑能改什么：可调面

AI 通过 `set_params` 提交一份 `StrategyConfig` 的**补丁**。可调面按风险方向分成三类：

| 类别 | 字段 | AI 权限 |
| --- | --- | --- |
| **策略面**（打什么牌） | `coinSource.*`（选币池、排序、最小成交量）、`indicators.*`、`promptProfile` | **自由调整** |
| **节奏面** | `intervalMinutes`（有下限）、`throttle.minHoldMinutes` | **自由调整**（频率只能调低不能调高，见下） |
| **风险面**（赌注多大） | `riskControl.*`、`circuitBreaker.*`、`throttle.maxEntries*`、`reentryCooldownMinutes` | **只能往更安全的方向调** |

**风险面的单向约束**：

- 杠杆、单笔名义价值、保证金占用、每小时/每轮开仓数 → **只能调低**
- 盈亏比下限、最小信心度、冷却时间 → **只能调高**
- `circuitBreaker.*`、`requireStopLoss` → **完全不可改**
- 暂停交易 → **可以**（而且这是它最重要的一个动作）

**为什么开仓频率只能调低**：实盘实测——策略**扣费前毛盈亏 ≈ 0**、
手续费占毛盈亏 **983%**。**高频在这个账户上被证明是亏损来源**。
所以 AI 可以提高频率的权限不存在：它想更激进，只能去改选币与择时，
不能靠多交易。

## 3. 硬上限：AI 永远碰不到的地板

**这是需要你拍板的唯一问题。**

我的建议：**AI 只能在"用户设定的上限之内"调整，上限本身只有你能改。**

具体地，配置里区分两组数字：

```
用户上限（只有人能改）     AI 可调区间
─────────────────────     ──────────────────────────
maxLeverageCeiling: 10  →  AI 可在 1–10 之间调
maxMarginPctCeiling: 50 →  AI 可在 1–50% 之间调
maxDailyLossPct: 5      →  AI 完全不可改
maxEntriesPerHourCeiling: 6 → AI 可在 1–6 之间调
```

**为什么不能让它改上限**：
- 风控引擎是这套系统**唯一的结构性保证**（`AGENTS.md` §2.1）。
- 一个能提高自己杠杆的智能体，离"一次错误反思 → 强平"只差一步。
- 而且**它越想盈利，越有动机提高上限** —— 这不是它"坏"，是目标的必然。
  给它一个盈利目标、又给它解开安全带的权限，等于**把安全带交给被考核的人管**。

**你如果希望它连上限也能动，我建议的折中**：上限只能在一段观察期之后、
且**必须由你点一下确认**才能放宽。我不会做成自动的。

## 4. 智能体循环（不用定时器，按需触发）

### 4.1 触发条件（任一满足）

| 触发 | 理由 |
| --- | --- |
| 有**新平仓结果**入账 | 唯一能产生真实反馈的事件 |
| 权益相对上次大脑决策变化 ≥ 2% | 显著变化值得重新判断 |
| 连续 3 笔亏损 | 可能参数与市场不匹配 |
| 距上次大脑决策超过 60 分钟 | 兜底，防止长时间不审视 |
| 风控连续拒绝 ≥ 5 次 | 参数与市场脱节，模型在做无效决策 |

### 4.2 预算（防止 token 爆炸）

- **每小时最多 6 次大脑调用**
- 每次循环**最多 8 步工具调用**
- 每次循环的提示词预算固定（记忆区块不裁，候选区块可裁 —— 沿用 §3 的取舍方向）

**为什么必须有预算**：你希望它"实时动态、按需多次"。但**没有上限的智能体循环
可以在一小时内烧掉几百次模型调用**。实测现在的单次决策约 5.8 万 tokens；
一个 8 步的循环就是数十万。所以预算是**这个模式能不能长期跑的前提**，不是限制。

### 4.3 工具面（提示词式工具调用）

模型客户端只有 `complete(system, prompt)`，**没有原生工具调用**。
所以采用**提示词式工具循环**：模型输出一个 JSON 工具调用，程序执行、把结果回喂，再让它继续。

**这反而更好**：与 LLM 厂商无关、不用改客户端、换模型不用改代码。

| 工具 | 作用 |
| --- | --- |
| `get_performance(window)` | 绩效：笔数、胜负、毛/费/净、盈亏比 |
| `get_equity_curve()` | 权益轨迹（判断回撤与恢复） |
| `get_experiments(limit)` | **它自己改过什么 + 之后发生了什么** ← 学习的核心 |
| `get_recent_decisions(limit)` | 它做过哪些决策、被风控拒过什么 |
| `get_market_overview()` | 候选池、波动率、成交量概览 |
| `get_current_params()` | 当前生效的参数 |
| `set_params(patch, reason)` | 改参数（**受第 2、3 节钳制**） |
| `pause_trading(reason)` | 暂停（只能收紧） |
| `finish(summary)` | 结束本轮 |

`set_params` **必须带 `reason`**，且钳制发生时要**如实记录被改成了什么**——
沿用 §2.1 的规矩：每一次运行时推翻模型都要留下痕迹。

## 5. 「越跑越厉害」靠什么成立

不是靠一句"请反思"，而是靠**一张实验记录表**：

每一次大脑调用落一行：

```
agent_experiments
  id, trader_id, created_at
  trigger            -- 为什么被唤醒（新结果 / 连亏 / 超时 …）
  observed           -- 唤醒时的绩效快照（JSON）
  patch_json         -- AI 想改什么
  applied_json       -- 守卫钳制后**实际**改了什么（两者不同时要能看出来）
  clamps_json        -- 哪几项被钳制、为什么
  reason             -- AI 自己写的判断
  tool_calls_json    -- 它查了什么（可还原它的推理依据）
  -- 下面是"之后发生了什么"，由后续周期回填：
  outcome_trades     -- 这次调整之后成交了几笔
  outcome_net_pnl    -- 净盈亏
  outcome_evaluated_at
```

**下次唤醒时，`get_experiments` 把这些连同结果一起喂回去。**
于是模型看到的是："我在累计亏损时把杠杆从 5 降到 3，之后 12 笔净 +0.31" ——
**这是一个有依据的事实，而不是一段自述**。

**这就是它与"定时问模型"的本质区别**：定时模式里，模型的每一次决策都是孤立的；
这里它有**自己的历史与后果**。

## 6. 如何验证它真的在变好（而不是感觉在变好）

**必须测出来，不能假设。** 三层证据：

1. **可解释性**：每次调整都能追到"它当时看到了什么、为什么这么改"（`agent_experiments` 全量落库）
2. **反向验证**：把 `get_experiments` 关掉（让它看不到自己的历史），
   在 `npm run sim:live` 上跑同样长度，比较两者的净值曲线。
   **如果关掉历史成绩反而更好，那么"反思"就是在制造噪音** —— 这种情况要能发现，
   而不是把它当成功上线。
3. **样本量纪律**：**少于 30 笔平仓不下结论**。图上看曲线"变好了"不算数。

**我在报告里不会写"它越跑越厉害"**，只会写"在这些样本下，开了历史反馈的一组净值为 X，
关掉的一组为 Y"。这是唯一诚实的说法。

## 9. 多智能体协同（修订：单一"大脑"不够）

单一智能体被要求同时做感知、分析、决策、反思，等于**让同一个人既当运动员又当裁判**。
更根本的问题是：**一个"想要交易"的智能体，没有动机去否决自己。**
真正常用的结构是**分权 + 对抗 + 并行**。

### 9.1 角色与职责

| 角色 | 职责 | 频率 | 它被允许做什么 |
| --- | --- | --- | --- |
| **策略师** | 定目标、合成各方结论、**最终决定参数** | 低频 | 写参数补丁（受第 2、3 节约束） |
| **绩效分析师** | 读绩效与权益轨迹，回答"现在到底是什么状态" | 低频 | 只读 |
| **归因分析师** | 回答"**最近的盈亏来自哪里**"：选币？择时？费用？运气？ | 低频 | 只读 |
| **风控官** | **对抗性审查**：给定提案，找出它会怎么亏 | 每次决策 | **只能否决或要求收紧，不能放行** |
| **行情分析师** ×N | 并行，各自盯一个假设（趋势/反转/量能/相对强弱…） | 每轮 | 只读 |
| **交易员** | 综合行情分析师的意见，产出具体提案 | 每轮 | 提案（不是决定） |
| **复盘员** | 每笔平仓后写因果结论，进记忆 | 每笔平仓 | 只读 + 写记忆 |

**一条不可动摇的分权规则**：

> **提出交易的人不能批准交易；批准交易的人不能改风控上限。**

风控官的角色是**结构性对抗**——它的提示词里写的是"**找出这个提案会怎么亏**"，
而不是"评估它好不好"。这跟人做交易时的独立风控是同一个道理：
**没有对抗的自我审查，会退化成给自己找理由。**

### 9.2 编排（借鉴 harness 的做法）

```
每次「交易台」决策：
  并行 ├─ 行情分析师 A（趋势假设）
       ├─ 行情分析师 B（反转假设）
       ├─ 行情分析师 C（量能/资金流假设）
       └─ 记忆检索（复盘员写下的、与当前标的相关的前车之鉴）
        ↓ 汇总
      交易员 —— 产出提案（含理由）
        ↓
      风控官 —— 对抗审查（只能否决/收紧）
        ↓
      程序风控引擎（第 3 层，最终裁决）
        ↓
      执行 + 落库

每次「策略师」调参：
  并行 ├─ 绩效分析师
       ├─ 归因分析师
       └─ 实验历史检索（它自己改过什么 + 之后发生了什么）
        ↓
      策略师 —— 参数补丁 + 理由
        ↓
      风控官 —— 对抗审查（重点：这个变更在什么情况下会让回撤失控）
        ↓
      程序守卫（单向约束 + 硬上限）
```

**关键点**：**并行只在"值得"的时候用。** 每次决策都开三个分析师，
token 成本是单次的数倍。所以：

- **常规轮次** → 单次调用（现在的模式）
- **有明确信号 / 仓位较大 / 接近风控边界** → 开并行分析
- **策略调参 / 大回撤后** → 开完整面板

**由程序决定用哪一档，而不是让 AI 自己决定**——否则它会为了"更严谨"而永远选最贵的那档。

### 9.3 上下文隔离（省钱且更准）

每个角色**只拿到它需要的东西**：

- 行情分析师：只拿它负责的那个假设所需的数据 + 标的快照。**不拿账户绩效**（那会干扰对行情的判断）。
- 风控官：拿提案 + 账户状态 + 历史同类失败案例。**不拿"这个提案多有吸引力"的论证**——对抗审查不应该被说服。
- 策略师：拿绩效、归因、实验历史。**不拿逐笔行情**。

**这既省 token，也避免角色之间互相污染判断。**

### 9.4 结构化结果，不是散文

每个角色返回**结构化 JSON**（论点、证据、置信度、请求的下一步），而不是一段话。
程序只认结构。**这是让多智能体可编排、可审计、可测试的前提**——
否则下游只能靠解析散文，那是不可靠的。

### 9.5 预算与并发上限（硬约束）

- **每轮决策最多 N 个并发子代理**（默认 3）
- **每小时总调用次数上限**（默认 40，含所有角色）
- **单次面板最多 8 步**
- 超预算时**降级到单次调用**，而不是报错中断

**预算是这个模式能不能长期跑的前提。** 实测量级参考：现在单次决策约 5.8 万 tokens；
一个三分析师 + 交易员 + 风控官的面板是**它的 4–5 倍**。没有上限，一天就能烧掉可观的钱。

### 9.6 记忆：让"越跑越厉害"落地

多智能体的价值不在于一次决策更聪明，而在于**它的结论能积累**：

- **复盘员**每笔平仓后写一条因果结论 → 进 `agent_memory`（按标的、按形态、按失败原因索引）
- **下一次决策时检索**相关的前车之鉴喂给交易员
- **策略师调参时**读 `agent_experiments`（改了什么 + 之后发生了什么）

**这才是"越跑越厉害"的机制**：不是模型变强了，是**它积累的证据变多了**，
而且这些证据是**结构化的、可检索的、带真实后果的**。

### 9.7 修订后的实现计划

在原 8 阶段前插入两阶段，并把 D 阶段改造为多角色：

| 阶段 | 内容 |
| --- | --- |
| **A. 数据层** | `M5`：`agent_experiments`、`agent_memory`、`agent_runs`（每次面板的完整轨迹） |
| **B. 守卫层** | `applyAgentPatch()` 纯函数 + 单向约束 |
| **C. 工具层** | 9 个只读/受控工具 |
| **D. 角色层** | 七种角色的提示词与**结构化输出 schema**，每个可独立单测 |
| **E. 编排层** | 并行 fan-out、对抗审查、降级策略、并发与预算上限 |
