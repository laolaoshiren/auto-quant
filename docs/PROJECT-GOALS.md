## 0. 一句话

**用自然语言定义策略的加密货币自动交易终端**：模型每周期读市场、做决策、下单、留下完整推理；
一个**独立于模型的风控引擎**审查并钳制每一张订单。

> 模型负责判断，运行时负责裁决。

## 1. 三条不可动摇的产品信条

1. **安全优先于功能**：会动真实资金。一个漂亮但风控有漏洞的版本，比朴素但可靠的版本危险得多。
2. **可验证优先于"看起来能用"**：任何功能必须能在不花钱的前提下验证（单测 → 模拟 → 回放）。
3. **每一笔账都可与交易所对账**：平台记录 + 机器人之外的活动 = 交易所钱包实际变动。

## 2. 优先级排序（任何取舍按这个顺序）

```
① 不出错（仓位失去保护 / 账目失真 = 最高优先级）
② 能验证（不能验证的功能是负担）
③ 扩展覆盖面（更多交易所 / 标的 / 交易形式）
④ 体验（界面、易用性、性能）—— 最后
```

## 4.1 长期开发方针（2026-11-10 用户指示，覆盖以后所有迭代）

1. **自查为主**：用户只提需求、定期整体查看。AI 完成需求后必须**自己验证**（真实运行/无头浏览器/测试），
   不靠想象、不把"编译通过"当"能用"；让用户重复检查出问题 = 返工，视为失败。
2. **浏览器一律用真实无头浏览器**（playwright-core + 本机 Chrome/Edge，`headless: true`），
   不得弹出可见窗口干扰用户；但必须是真实渲染（与真人看到一致），不能只读代码或 mock。
3. **技术方案自己定**：不拿技术选项问用户（只问产品取舍/资金/实盘安排）。
4. **实盘只用子账户**：主账户有实盘项目在跑，绝不能动；子账户没钱，用于接线/冒烟测试。
5. **采用最新、最标准的方案**：不迁就过时/不标准的遗留实现（尤其 AI 工具调用必须是标准
   function calling）；清理旧方案时保持"行为可验证"。
6. **演示数据优先**：开发与验收尽量基于**演示数据模式**（模拟各种实盘数据），
   不等待真实跑单才能验证 UI/功能。
7. **本地演示服务常驻**：保持一个本地演示实例运行，方便用户随时查看进度。
8. **用户工作量最小化**（2026-11-10 用户指示）：用户只提需求、看结果；
   实现、测试、回归、文案同步、文档同步、死代码清理全由 AI 完成。
   **让用户当 QA 是失败** —— 用户重复检查出问题 = 返工。
9. **需求闭环 + 越用越懂用户**：每个需求走完
   ①实现 → ②影响面扫描（文案/引用/测试/文档/死代码）→ ③相关页面跟随改
   → ④真实环境验证 → ⑤提交推送 → ⑥汇报；从每次反馈提炼成规则写进 `AGENTS.md`，
   让后续会话直接继承 —— 同一类问题不问第二次、不犯第二次。
10. **主动安排测试的人**：用 Agent Team 做独立交叉验证（一个 agent 实现、另一个按用户视角回归），
   问题能修就修、不能修写清原因。

## 5. 用户偏好（协作层面的红线）

- **发现代码级 BUG 直接修**，不用停下来问；
- **策略性改动（风控参数/交易行为/默认值/提示词倾向）先说明取舍再动手**；
- 报告用中文、简短、结果在前（表格 + 少量 emoji），不贴大段代码；
- 不确定就说不确定，不把推测写成已验证；
- 推送：大的/多天的迭代可自行推送；小的等用户安排；不要反复问；
- 实盘测试只用**子账号**，服务器上做；主账户不动。
