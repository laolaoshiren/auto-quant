## 0. 一句话

**用自然语言定义策略的加密货币自动交易终端**：模型每周期读市场、做决策、下单、留下完整推理；
一个**独立于模型的风控引擎**审查并钳制每一张订单。

> 模型负责判断，运行时负责裁决。

## 1. 三条不可动摇的产品信条

1. **安全优先于功能**：会动真实资金。一个漂亮但风控有漏洞的版本，比朴素但可靠的版本危险得多。
2. **可验证优先于"看起来能用"**：任何功能必须能在不花钱的前提下验证（单测 → 模拟 → 回放）。
3. **每一笔账都可与交易所对账**：平台记录 + 机器人之外的活动 = 交易所钱包实际变动。

## 2. 优先级排序（任何取舍按这个顺序）

```
① 不出错（仓位失去保护 / 账目失真 = 最高优先级）
② 能验证（不能验证的功能是负担）
③ 扩展覆盖面（更多交易所 / 标的 / 交易形式）
④ 体验（界面、易用性、性能）—— 最后
```

## 3. 当前阶段（2026-11 基线）

- 版本 **v0.2.0**，核心链路「自然语言策略 → 硬风控 → 执行 → 完整审计」已实盘验证。
- 四种运行模式：固定策略 / AI 托管 / 多智能体团队 / JEV（实验性）。
- **2026-11 完成了一轮"地基加固"**：模拟盘可信化（撮合/守卫/成本口径）、信号健康度接线、
  运行期配置守卫、文档归档与工程校准、DSH 多 Agent 工作流手册。
- **后续开发以本地模拟盘为主**；实盘验证只在服务器上用**子账号**做。

## 4. 明确不做 / 暂缓（避免重复讨论）

| 事项 | 原因 |
|---|---|
| UI/UX 视觉与交互打磨 | 用户 2026-11-09：先整理基础框架，后续再慢慢开发（只修客观缺陷） |
| 替 magpie 网关做上游选择/路由/分组/熔断 | 网关的事实由网关掌握（见 `docs/AGENTS.md` magpie 边界节） |
| 为"跑通"放宽风控参数 | 绝对禁止；需要放宽 → 产品决策，先说明 |
| 引入需要编译的原生依赖 | `node:sqlite` 等刻意的无构建选择（`docs/DEVELOPMENT.md`） |
| 站点信息入仓库 | 只写本地不入库文件（根 `AGENTS.md`、`deploy.local.ps1`、`.dsh/`） |

## 5. 用户偏好（协作层面的红线）

- **发现代码级 BUG 直接修**，不用停下来问；
- **策略性改动（风控参数/交易行为/默认值/提示词倾向）先说明取舍再动手**；
- 报告用中文、简短、结果在前（表格 + 少量 emoji），不贴大段代码；
- 不确定就说不确定，不把推测写成已验证；
- 推送：大的/多天的迭代可自行推送；小的等用户安排；不要反复问；
- 实盘测试只用**子账号**，服务器上做；主账户不动。

## 6. 验收底线（任何改动）

```text
npm run typecheck           # 0 退出
npm test                    # 全绿
npm run lint / build        # 改前端时
npm run sim                 # 碰交易链路时，必须 18/18
npm run check:routes        # 改接口时
npm run check:links         # 改文档时
node scripts/generate-notices.mjs --check   # 改依赖时
```

碰真实资金/接线时，必须说明验证到哪一档（`docs/AGENTS.md` §6 的阶梯）。
