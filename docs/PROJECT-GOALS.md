## 0. 一句话

**用自然语言定义策略的加密货币自动交易终端**：模型每周期读市场、做决策、下单、留下完整推理；
一个**独立于模型的风控引擎**审查并钳制每一张订单。

> 模型负责判断，运行时负责裁决。

## 1. 三条不可动摇的产品信条

1. **安全优先于功能**：会动真实资金。一个漂亮但风控有漏洞的版本，比朴素但可靠的版本危险得多。
2. **可验证优先于"看起来能用"**：任何功能必须能在不花钱的前提下验证（单测 → 模拟 → 回放）。
3. **每一笔账都可与交易所对账**：平台记录 + 机器人之外的活动 = 交易所钱包实际变动。

## 2. 优先级排序（任何取舍按这个顺序）

```
① 不出错（仓位失去保护 / 账目失真 = 最高优先级）
② 能验证（不能验证的功能是负担）
③ 扩展覆盖面（更多交易所 / 标的 / 交易形式）
④ 体验（界面、易用性、性能）—— 最后
```

## 4.1 长期开发方针（2026-11-26 更新）

1. **自查为主**：用户只提需求、看结果。AI 完成需求后必须**自己验证**（单测 / 模拟盘 / 线上回读 / 内置浏览器），不把"编译通过"当"能用"。
2. **浏览器巡检以内置真实浏览器为主**（废止旧 `playwright-core` 无头脚本与 `ui:smoke` 包袱），直连目标页面点按交互、核验深/浅主题、检查控制台与视觉排版。
3. **技术方案自己定**：不拿纯技术选项打扰用户（只问产品取舍 / 策略方向 / 资金安排）。
4. **实盘只用子账户**：主账户运行真实项目，绝不拿它做测试或冒烟。
5. **采用最新、最标准的方案**：坚持标准 function calling、增量部署与模块化架构，及时清理死代码与历史包袱。
6. **测试环境以服务器为主**：本地保持干净（单元/类型/构建/`sim`），部署走自动增量 `deploy.ps1` 并在服务器验证。
7. **用户工作量最小化**：实现、测试、回归、文档同步、死代码清理、自动推送全由 AI 闭环。
8. **需求闭环 + 越用越懂用户**：① 实现 → ② 影响面扫描 → ③ 关联同步 → ④ 验证 → ⑤ 提交/部署/自动推送 → ⑥ 精简汇报；从每次反馈提炼规则持久化到 `AGENTS.md`。
9. **复杂并行用 `/swarm` 交叉把关**：多战线重构/大清理走隔离 worktree 并行 + 独立 `verifier` 审查 + `integrator` 合入回归。

## 5. 用户偏好（协作层面的红线）

- **发现代码级 BUG 直接修**，不用停下来问；
- **策略性改动（风控参数/交易行为/默认值/提示词倾向）先说明取舍再动手**；
- 报告用中文、简短、结果在前（表格 + 少量 emoji），不贴大段代码；
- 不确定就说不确定，不把推测写成已验证；
- **推送（2026-11-26 更新）**：正常完整的功能改动 / Bug 修复验证全绿后**自动单次推送 GitHub**；预期还要多次协商微调的短期小改动先本地提交暂存，定稿后再合推一次（严守低频、单次 push、禁用 `gh` 轮询/批处理）；
- 实盘测试只用**子账号**，服务器上做；主账户不动。
