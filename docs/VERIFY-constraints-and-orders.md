# 核实：硬性约束是否写死、挂单是否过期

**时间**：2026-09-18
**背景**：用户提出两个问题 ——（1）提示词里的「硬性约束」是否写死、AI 后续能不能改；
（2）「当前委托」里的挂单是不是过期的、系统有没有取消机制。

---

## 一、问题 1：硬性约束**不是**写死的，AI 改得动

**提示词里那段「硬性约束」是从 AI 那份配置（`agent_config_json`）实时渲染出来的** ——
它显示的就是 AI 当前的值，AI 改一次它跟着变。

### 证据：AI 确实改过风控参数

| 实验 | 改了什么 |
| --- | --- |
| #2 | `altcoinMaxPositionValueRatio` **0.5 → 1**（单仓名义上限） |
| #4 | `minPositionSize` → **6** |
| #5 | `minPositionSize` **6 → 5.5** |
| #3 / #6 | **改写它自己的「决策流程」** |

**其中 `altcoinMaxPositionValueRatio` 就是提示词里那行「单仓名义价值上限」的来源** ——
它被 AI 从 0.5 改成了 1。

### 那为什么历史成交全是 3x？

因为 **`defaultLeverage` / `btcEthMaxLeverage` / `altcoinMaxLeverage` 都还是 3** ——
**AI 没有提高杠杆上限。**

模型每笔都自己填 `leverage` 字段，**但上限是 3，超过就被风控钳到 3。**

**所以"全是 3x"不是写死，是 AI 没动杠杆这一项。**
而提高杠杆是真实的风险放大 —— **它保守在这里是对的。**

## 二、问题 2：挂单**不是**过期的，清理是即时的

```
02:09:58  对账结清了 2 张（SOLUSDT 止盈、止损）   ← 与平仓同一秒
01:37:34  对账结清了 2 张（XRPUSDT 止盈、止损）   ← 与平仓同一秒
00:06:57  对账结清了 2 张（HYPEUSDT 止盈、止损）
19:51:57  对账结清了 2 张（XRPUSDT 止盈、止损）
17:45:57  对账结清了 2 张（HYPEUSDT 止盈、止损）
16:33:57  对账结清了 2 张（SOLUSDT 止盈、止损）
```

**延迟 0 秒**：平仓的同一秒，那两张保护单被标成终态。

机制：`settleStaleOrders()`（`autoTrader.ts` L2156），挂在历史对账那一遍里，
**每轮周期都跑**。

### 当前状态（浏览器实测）

```
标签：当前委托 2
表体：HYPEUSDT 止盈 + HYPEUSDT 止损   ← 正好对应 1 个持仓
数据库：NEW 2 张
```

**界面与数据库完全一致。** 用户截图里的 10 张是**瞬时状态**，
不是"系统缺这个功能"。

## 四、这两轮我在方法上的同一个毛病

**两次都下结论太快：**

1. **第 5 轮**：看到「零 open_short」就断定提示词偏多 —— **只看了 4 条记录**，
   而完整数据里 #144 早就算过一笔完整的做空盈亏比。
2. **这两问**：用户看到的「10 张挂单」和「全是 3x」都是**某个时刻的快照**，
   而它们背后各有一个需要查日志/查实验记录才能回答的机制。

**共同点：把一个显眼的观察，当成了需要机制解释的系统的全部。**

**正确做法**：先问「这个数字是在什么条件下产生的、它会不会随时间变化」，
再去查机制。**快照不等于状态，状态不等于机制。**
