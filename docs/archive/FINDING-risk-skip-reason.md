# 风控官的"没审阅"有三种原因，而审计块把它们写成同一句（2026-10-15 修）

> 这是本轮第二处**同类病**：审计文案把**正常**说成**异常**。

---

## 1. 症状

`#11` 团队模式的审计块里，`<risk>` 块有 **74%** 的轮次是这一句：

```
⚠️ 本轮**未经风控官审阅**（风控角色未启用或调用失败）—— 决策按裁决官结论直接放行。
```

而实测 272 轮的分布：
```
未经审阅: 202 轮（74%）
已审阅:    70 轮
```

**74% 都"未启用或调用失败"？** 那不合理 —— 风控官显然没有一直坏着。

---

## 2. 真因：三种原因被写成同一句

`askRiskOfficer` 返回 `null` 有三种来源（`routedModel.ts`）：

```
① decisions.length === 0   → 没有决策要审（本轮本来就不行动）
② !hasAction（全是 skip）   → 【设计内跳过】"没有动作就没有风险敞口可审"
③ catch 抛错                → 真的调用失败
```

而 **② 是绝大多数**（团队动作率只有约 10%，所以大部分轮次裁决全是 `skip`）。

### ② 是**有意优化**，不是失败

代码注释写明了它的来历：
```
实测背景（第 39 轮把耗时结构定位清楚）：
  4 个分析师（并行）：~50 秒
  辩论 → 裁决 → 风控：~370 秒     ← 瓶颈
而这三次串行 T3 调用不能并行（P1：唯一裁决者）。
所以省时间的唯一办法是少调用一次 —— 而这一条正是安全的省略：
没有动作时，风控的结论必然是"批准"（没什么可否决的）。
```

并且它**不影响物理底线**：
```
风控官的两层结构里，代码层的物理底线（RiskEngine）不受影响 ——
它仍然会跑，仍然会拦下保证金不足、数量不可交易、没有止损的动作。
跳过的只是"智能体层的策略审阅"。
```

⇒ **跳过是正常的、有意的、安全的**，而文案说它"未启用或调用失败"。

---

## 3. 为什么这是真问题

```
操作员看到"调用失败" → 去查风控官为什么坏
                       → 查不到（因为它没坏）
                       → 下一次再看到同一句话，就不再当回事
                       → 于是【真的】调用失败时也没人查
```

**这与"把故障说成观望"（`decisionZeroState.ts` 那条）是同一类病、方向相反：**
```
那条：故障 → 说成正常（让人不去查该查的）
这条：正常 → 说成故障（让人去查不该查的）
```
两者都让审计记录失去可信度。

---

## 4. 修法

### 4.1 判据抽成一份（`agent/nonAction.ts`）

```ts
export const NON_ACTION: ReadonlySet<string> = new Set(['skip', 'hold', 'wait']);

export function allNonAction(decisions: readonly { action: string }[]): boolean {
  return decisions.length > 0 && decisions.every((d) => NON_ACTION.has(d.action));
}
```

⚠️ **必须只有一份** —— `askRiskOfficer` 用它决定"要不要叫风控官"，
渲染层用它决定"文案怎么写"。各写一份就会出现
"跳过是因为全是 skip、文案却说调用失败"的自相矛盾审计记录。

⚠️ 用**黑名单**（fail-closed）：只有明确属于"不行动"的三个才跳过，
其余（含**将来新增的动作**）一律送去风控。白名单反推会让新动作默认不被审。

### 4.2 三种原因分开写

```
all_non_action → ✅ 本轮**无需风控官审阅** —— 裁决结果是"全部不行动"，
                    没有风险敞口可审（这是设计内的省略，不是失败）。
call_failed    → ⚠️ 本轮**未经风控官审阅**（**调用失败**）—— 决策按裁决官结论直接放行。
not_enabled    → ⚠️ 本轮**未经风控官审阅**（风控角色**未启用**）—— 同上。
（都判不出）    → ⚠️ 本轮**未经风控官审阅**（原因未记录）—— 同上。
```

**最后一条刻意"不猜"**：`call_failed` / `not_enabled` 的信息在
`askRiskOfficer` 的 `onStep` 里，没有回传给调用方。如实说"原因未记录"
比猜一个原因好（**猜错比不写更糟**）。

---

## 5. 验证

单测 4 条（`riskSkipReason.test.ts`），关键是**互斥性**：
```
全是 skip → 必须出现"无需风控官审阅"，且【不能出现】"调用失败"/"未启用"
有真实动作 → 必须出现"未经风控官审阅"，且【不能出现】"无需审阅"
```
只加新文案不够 —— 旧的误导性措辞必须消失，否则等于没改。

⚠️ 线上验证需要等新代码跑出若干轮（部署后 0 轮时无法验证）。

---

## 6. ⚠️ 一处我**没有**改的东西（诚实说明）

`#11` 的动作率只有约 10%，意味着 **74% 的轮次风控官根本不参与**。
「风控官应该更常参与吗」是一个**产品问题**，不是 bug：

```
若把"全是 skip 也送去审阅"：
  · 代价：每轮多约 120 秒（T2_mid 串行）
  · 收益：几乎为零（没有动作，风控的结论必然是"批准"）
⇒ 代码里的选择（跳过）是对的。
```

但如果将来希望"风控官对'什么都不做'也表态"（例如"你已经 40 轮没动了，
我建议放宽标准"），那需要的是**另一个岗位**（组合管理 / 风格负责），
而不是把风控官叫来审一个空提案。这一点记在这里，留给后续决策。
