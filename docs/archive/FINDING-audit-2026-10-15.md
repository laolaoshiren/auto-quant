## ⚠️ 两条审计表述需要修正（我核实后发现的）

### A. 「`ROLES` 里 6/10 角色的提示词没送到」—— 不准确

真相（实测 `tradingDesk` 源码里的 `role: 'x'` vs `ROLES` 的键）：

```
tradingDesk 问 10 个角色，其中【7 个根本不在 ROLES 里】：
  bear · bull · judge · newscaster · sentiment · supervisor · technical
  ⇒ 它们【从来没有提示词可送】—— 不是"接线漏了"，是【编制表不完整】

ROLES 里有的 4 个（risk_officer / market_analyst / reporter / symbol_scout）
  → 本次修复后已能送达
```

**这个区别很重要**：前者要"补提示词"（写 7 份），后者是"接线"（已修）。
混为一谈会让人以为修完接线就万事大吉。

⚠️ 而 `judge`（裁决官）与 `bull`/`bear`（多空对抗）**没有提示词**是**决策核心的缺口** ——
它们目前只靠 `tradingDesk` 里的内联 task 短句工作。**这是待办，不是已修。**

### B. 「`symbol_scout` 未送达」—— 是我测试环境的问题，不是代码缺陷

```
它只在 AQ_PER_SYMBOL=on 时被问（线上确实开着）
而我的测试没设这个环境变量 → 那一轮压根没问它 → 测试报"未送达"
```

**教训：判据要能覆盖到目标，否则会让人去修一个不存在的 bug。**

### 待办核实结果（2026-11-09，只读审计）

**① 版本号三来源不一致 —— 核实后：`package.json` 已不再停在 `0.1.0`；剩下的一处文档已修。**

| 声称的"来源" | 核实结果 |
| --- | --- |
| `package.json` | 根与三个 workspace 都是 **`0.2.0`**（`git describe` 为 `v0.2.0-29-g47f2d2c`）。原来那句"恒 `0.1.0`"已不成立 |
| `build-info.json` | **不是源码**：`.gitignore:61` 明确排除它，它是 `scripts/deploy.ps1` 每次部署覆盖的**构建产物**。本地文件停在旧提交（`86dce7a`）只说明"上次部署的是那一版"，不影响仓库状态 |
| `docs/LEGAL.md` | 原文「仓库当前版本号是 `0.1.0`，尚无正式发布标签」**是过时事实**（本地已有 `v0.1.0` ~ `v0.2.0` 标签）。已在同一次改动里改为以根 `package.json` 为准 |
| `CHANGELOG.md` | 正文只到 `0.1.0`。`docs/RELEASING.md` 已把它列为**发版流程要恢复的项目**（不是代码缺陷），本次不改 |

⇒ 结论：**这条待办可以关闭**。"三来源"里真正的源码来源只有 `package.json`；`build-info.json`
是产物，文档那处已同步。

**② 手续费/资金费口径差（`-0.78` / `-0.24`）—— 只核实，未改任何金额算术。**

数字来源：`docs/ONEOFF-ledger-correction-10.md` 第 4 节的"三角对照"（2026-10-15 对 `#10`
某时间窗的快照）：

```
分项        交易所      账本        差
手续费      -3.9422   -4.7250     -0.7828
资金费       0.1213   -0.1174     -0.2387
```

核实到的**代码口径**（2026-11-09 的 main）：

- **手续费**：只认 `/fapi/v1/income` 的 `COMMISSION`、且只算**结算资产**（USDT）计价的那部分
  （`packages/server/src/binance/income.ts` 的 `commissionInWindow()` 注释）；
  非结算资产（BNB 抵扣）按 `docs/AGENTS.md` §2.5 **不计入 `fee`**，
  它和 USDT 不是同一单位。因此「账户级 COMMISSION 合计」与「`trades.fee` 合计」
  **本来就允许不同**（只要有 BNB 抵扣、或有未平仓仓位的入场费）。
- **资金费**：`trades.funding_fee` 只在**平仓时**按该回合的生命周期聚合
  （`income.fundingInWindow()`）；**未平仓**持仓期间的资金费不在 `trades` 里。
  总账校验那一侧已经把未平仓的入场费与资金费单独加回去（`autoTrader.ts` 的
  `openHoldings` 注释记录了"符号写反导致平台侧被高估两倍手续费"那次事故）。
  两边口径目前是**对齐的**（同一时间窗 + 未平仓成本单列）。

⇒ **最可能的解释是口径差（账户级流水 vs 已平仓账本），而不是记账 bug** ——
但这**只是推断**：要证实它需要生产库与同一时间窗的 `income` 流水，而 `data/` 是禁止触碰的。
建议：在一台能读生产库的环境上按 `ONEOFF-ledger-correction-10.md` 第 5 节的教训重跑三角对照
（**用与平台同窗的流水**，并把未平仓入场费/资金费单列），确认后把结论写进本文件。
**在确认之前不要改 `trades.insert()` / `applyExchangeFigures()` 的算术。**
