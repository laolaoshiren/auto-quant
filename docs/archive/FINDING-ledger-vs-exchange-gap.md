## 0. 结论摘要

```
✅ 已用第三方口径独立验证（2026-10-15，直接问币安，不经平台计算）：

   USDT 钱包余额: 93.09371459
   本金:          100.05
   真实收益:      -6.9563 USDT  →  【-6.95%】

   验算: 100.05 − 6.956285 = 93.093715   ← 与钱包余额精确到小数点后 8 位

   ⇒ 平台的 exchangeNet = -6.956285 【正确】

   ⇒ **这台实盘机器人实际是亏的（-6.95%），而界面上显示的是赚 +5.65%**
```

## 0b. 根因与修法

```
根因：`reconciled_reversed`（方向重建反了的回合）按【标的 + 时间窗口】聚合已实现盈亏，
      而那些窗口平均 23.1 小时、最大 159.3 小时（其他平仓类只有 2–3 小时）
      → 窗口跨过多个真实回合，把它们的盈亏又聚合了一遍（各自已记过账）
      → platformSelf 虚增 13.06

修法：`income.tradeId` 等于成交的 `id`（实测 19/19 全部对上）
      → 改按成交 id 精确归属，与手续费那侧"按单号而不是按标的"同源
      → 提交 `4efe27b`

验证：去掉这类记录后 5.6573 − 13.0577 = −7.4004，与交易所 −6.9563 只差 0.4439
      （差两个数量级）
```

⚠️ **这个 12.6 是历史遗留、不会继续增长**：那 38 笔集中在 `10-03 → 10-12`，
`10-15` 之后**新增 0 笔**。所以修复的意义是"防止未来再发生"，不是"让这个数字归零"。

⚠️ **历史账本里的 +5.65% 需要重写才会变成 −6.95%** —— 那是改历史数据，
**我没有动它**（见第 5 节 ④）。在那之前，界面上的"累计盈亏 +5.65%"是**错的**。

## 3. 这一类是什么：方向不可信、金额来自流水

代码在 `autoTrader.ts:6348`。它的注释（`6276-6281`）写着：

> 「**开/平方向、数量与价位都不可信**，但净额仍按交易所口径记账。
>  这通常说明成交历史的窗口起点落在持仓中间，净头寸法把开/平判反了。」

而金额取的是交易所流水（`realizedInWindow`），**不是**重建的推测 —— 那部分设计是对的。

### ⚠️ 但它留下了 `entry_price` / `exit_price` / `side` 三个**不可信**的字段

实测那 38 笔里，**16 笔的"价格方向"与"盈亏符号"自相矛盾**：

```

MANAUSDT 空 入 0.10488  出 0.1005   价-4.18%（该赚）  实记  -0.01    ❌
SUIUSDT  空 入 1.194    出 1.2008   价+0.57%（该亏）  实记  +0.4289  ❌

NEARUSDT 空 入 5.285    出 5.285    价+0.00%（该亏）  实记  +1.3183  ❌

```

**对照**：`stop_loss` 的 45 笔**全部自洽**（0 笔矛盾）。

⇒ 所以矛盾**只出现在这一类**，而且与它的注释一致（"方向不可信"）。
**金额是对的（来自流水），价格与方向是错的。**

## 4. 为什么这仍然是个真问题

```
① 任何按 side/entry/exit 重算的消费者都会算错
   —— 例如 `reasonFromPrice`、胜率统计、归因分析
② 更严重的是：它让【账本】与【交易所】对不上 12.6
   —— 而"账本可信"是这套系统一切结论的前提
③ 我在排查过程中被它误导过一次：
   一度以为"take_profit 却在亏损"是执行 BUG，真实原因是
   这一类记录的价格字段不可信
```

⚠️ **重复记账的嫌疑已排除**：按 `symbol + closed_at` 去重，38 笔**没有重复行**。
所以差额不是"同一笔记了两遍"，而是**别的来源**（尚未定位）。
