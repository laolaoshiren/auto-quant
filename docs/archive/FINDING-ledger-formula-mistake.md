# 账本校正的两处错误与我怎么修的（2026-10-15）

> 本文记我在**一次性校正脚本**里犯的两个错，以及事后加的守卫。
>
> 教训的核心一句话：**仓库里已经有正确的算式（`netPnlOf`），我却又拼了一遍，并且抄错了。**

---

## 1. 我犯了什么错

校正 `#10` 的 38 笔 `reconciled_reversed` 时，我的脚本
（`scripts/oneoff/fix-ledger-reconciled-reversed.ts`）里写：

```ts
const newNet = newGross - row.fee - row.funding_fee;   // ❌ 两处错
```

而平台的不变量是（`packages/server/src/binance/income.ts` 的 `netPnlOf`）：

```ts
net = grossPnl − fee + fundingFee
                       ↑ 【加】
```

**为什么是加**：币安 `income` 里资金费**支出为负、收入为正**，
所以它是"已经带符号的量"，直接加进总额即可。手续费则相反（交易所报的是负数，
平台内部统一成"支出为正"，所以是减）。

### 错误①：资金费符号

```
  实测铁证：5 行的差值正好是 2 × funding_fee
    #309  funding=-0.000354 → 差 -0.000708
    #344  funding=-0.004143 → 差 -0.008286
    #355  funding=+0.003315 → 差 +0.006630
```

### 错误②：用了旧的 `row.fee`

那个 `fee` 是**按错误的窗口聚合**出来的（那正是这次校正要修的东西）。
真实的费在 `trip.entryFee + trip.exitFee` 里，**我拿到了却没用**。

---

## 2. 后果

```
改前：5 行全部自洽（net = pnl − fee + funding）✅
改后：5 行全部不自洽 ❌（合计差 -0.003075）
```

⚠️ 这个不变量是 `docs/AGENTS.md` §2.5 的**硬要求** ——
"账目必须能与交易所对得上"。留 5 行违反它，等于让"用毛/费/资金费复算净额"
在 5 行上失效，而下一个排查的人会以为那是数据损坏。

---

## 3. 修法：**只对齐 `fee`，让 `net` 保持不变**

```
  net = pnl − fee + funding   ⇒   fee = pnl + funding − net
```

**为什么不改成"用回合自己的费"**（我先试了，dry-run 拦住了）：

```
  用 trip.entryFee + trip.exitFee 重算 ⇒ 残差 -0.6967 → -0.9694（恶化）
  原因：那两侧费含【整个回合的所有成交】，而部分成交已被【相邻回合】认领过
        （就是早先发现的"穿零翻转"）⇒ 重复计费
```

所以正确方向是：**`net_pnl` 是校正的目标值（它来自按成交 id 的精确归属），
把 `fee` 对齐过去**，而不是反过来。

### 执行结果

```
不自洽的行: 0（原 5 行）
账本 192 笔 · 毛 -3.339294 · 费 4.72805 · 资金费 0.117394 · 净 -7.94995
内部自洽: ✅
而 net 保持 -7.94995 不变（残差仍是 0.6967，未恶化）
```

## 4. 加的守卫（`netPnlSingleSource.test.ts`）

三条，全部有反向验证：

```
① 净盈亏的算式不能有第二份副本
   判据：扫 packages/*/src 与 scripts/ 的 .ts，
        同一行里既有 `- xxxfee` 又有 `- xxxfunding` ⇒ 命中
   ✅ 反向验证：放一个 `gross - fee - funding` 进去，测试立刻变红并指出行号

② netPnlOf 必须只有一处定义
③ netPnlOf 的算式必须是"减费、加资金费"（钉住那个符号）
```

---

## 5. ⚠️ 写这条守卫时我又踩了三个坑（都记下来）

```
① 注释里写 `packages/*/src` —— 那个 `*/` 提前闭合了块注释，
   导致整个文件语法错误（TypeScript 报错位置在几十行之后）
   ⇒ 与 2026-10-15 那次 `open_*/add_to_position` 完全同形。**第二次了。**

② 判据把自己算了进去 —— "netPnlOf 应当只有一处定义" 报"实际 2 处：
   income.ts、netPnlSingleSource.test.ts"，因为**本文件里的正则字面量**
   `/export function netPnlOf\b/` 被它自己匹配到了
   ⇒ 判据的输入里混进了判据自己

③ walk() 第一版用 `readdirSync(full).length >= 0` 判"是不是目录" ——
   逻辑绕且错（`.ts` 文件也会被试一次）。改用 `statSync(full).isDirectory()`
```

**共同点：判据本身的正确性没人守。** 所以每条守卫都做了一次**反向验证**
（故意放一个该被抓的东西，确认它变红）—— 那是唯一能证明"守卫不是摆设"的办法。

---

## 6. 这次事故的真正教训

`netPnlOf` 的注释里**早就写明**：

> 修之前，同一个算式在仓库里有**五处**副本（`repositories.ts` 两处、
> `autoTrader.ts` 三处），于是同一个符号错误也复制了五份。
> §5.4 说"金额相关的算术只在一个地方算" —— 这就是那条规则的用处。

而**我刚刚又造了第六份副本，并且抄错了**。

```
为什么抄错：写一次性脚本时，我"凭印象"拼了那个算式，
           而没有去读仓库里已有的那一个。
⇒ 教训：**要写一个已经在仓库里存在的算式时，先 grep 它，不要凭记忆。**
```
