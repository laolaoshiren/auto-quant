# 猎手"零产出"：41/277 轮撞上轮数上限，而产出为零（2026-10-15 修）

> 这是本轮发现的**第三个"机器读的东西排在最后"**的缺陷 ——
> 与裁决官截断（`FINDING-judge-output-truncation.md`）**完全同形**。

---

## 1. 症状

`#11` 团队模式的情报猎手（Claude Code harness，需求④）**经常什么都没查出来**。

线上原文（第 277 轮，`newscaster` 角色自述）：
```
全部四个猎手（news_hunter、flow_hunter、community_hunter、macro_hunter）
均因 Reached max turns (12) 报错，未返回任何新闻条目、来源链接或发布时间

本轮四个情报猎手全部执行失败（均达到最大轮次上限），未提供任何可用新闻材料
```

## 2. 量化

```
含 "Reached max turns" 的轮次: 41 / 277（15%）
其中【有部分产出】的:          0 / 41        ← 关键
按天: 10-13: 5 次 · 10-14: 100 次 · 10-15: 16 次（共 121 次）
```

**"撞上限"本身不是问题**（`harness.ts` 已经处理：撞上限但有文本就收下，
并在 `error` 里说明"产出可能不完整"）。

**问题是产出为零** —— 那层没有文本可收。

## 3. 根因：与裁决官那次**完全同形**

```
裁决官：把推理写在数组【前面】 → 输出预算用尽时从末尾砍 → 数组被砍掉 → decisions=[]
猎手：  把"搜完所有来源"排在"写结论"【前面】 → 轮数用尽 → 什么都没写 → 零产出
```

两次都是**机器读的东西排在最后**，而截断发生在最后。

### 3.1 `maxTurns = 12` 的来历（以及它错在哪）

`harness.ts` 的注释：
```
实测对照（同一个真实猎手任务）：
  不限轮数（线上）      → 600 秒超时，0 字产出
  --max-turns 10        → 86.1 秒，正常完成（2 次 WebSearch）
  --max-turns 4         → 报 "Reached max turns"，但也没超时

取值：默认 12 —— 实测 2 次搜索完成，留 6 倍余量
```

⚠️ **"6 倍余量"这个推断基于一次实测。** 而猎手任务是**多标的**的
（实测候选池 18–20 个），且要求"最近 48 小时内"——
那意味着它要对多个标的分别搜、还要筛掉旧闻。**12 轮不够。**

## 4. 修法（两层，缺一不可）

### ① 提示词：把"先给结论"写成硬纪律（`hunters.ts`）

```
## ⚠️ 输出时机（这条有实测代价，必须遵守）
**先输出 JSON 数组，再去搜更多来源。** 顺序不能反 ——
系统给你**有限的搜索轮数**，用尽时进程会被直接截断。
实测代价：第一版让它"搜完所有来源再写"，于是**41 轮里产出为零**
（它一直在搜，从未写下任何东西）。
所以：**搜到第一条就够了 → 立刻写出数组 → 再决定要不要继续搜**。
```

⚠️ **这段必须排在"优先看这些来源"之前** —— 我第一版放在之后，
而 `hunterOutputFirst.test.ts` 立刻变红，判据是**位置**而不是"存在"：
```
模型读到的最后一条指令仍然是"多搜来源" ⇒ 它就会继续搜
```
**顺序即优先级。**

### ② 轮数上限 12 → 24（`harness.ts`）

给"多标的 + 筛时效"留空间。⚠️ 超时 600 秒仍远大于 24 轮的实际耗时
（实测 10 轮 ≈ 86 秒），所以加轮数不引入超时风险。

## 5. 验证

4 条单测（`hunterOutputFirst.test.ts`）：
```
① "先输出数组"必须排在"看来源"之前（判据是位置）
② 必须说明"轮数用尽会被截断"（给理由，不只是命令）
③ 【反向守卫】不能因为这次改动而放松"不许编造"
   —— 那会让猎手编一条假新闻来满足"先写数组"，比零产出糟得多
④ 每个猎手都要拿到这条纪律（不是只改了一个）
```

⚠️ 线上验证需要等猎手跑出若干轮（它们按需触发，不是每轮都跑）。

---

## 6. 一条更普遍的规律（三个同类缺陷了）

```
① 裁决官：理由在前、数组在后 → 预算用尽 → 决策全丢
② 风控官：把"设计内跳过"写成"调用失败" → 审计记录失去可信度
③ 猎手：  搜索在前、结论在后 → 轮数用尽 → 零产出
```

**共同点：让"机器读的东西"或"真相"排在最后，而截断/渲染发生在最后。**

⇒ 可复用的检查：**任何"有限预算 + 从末尾截断"的路径，
都要问"最先被截掉的是什么，而它是不是最重要的那个"。**
