# 团队模式动作率分析（2026-10-15）

> 问题：「`#11` 团队模式 235 轮里只有 33 轮有动作（24.1%）—— 这是"正确的保守"还是"结构性缺陷"？」
>
> **结论：是"规则内的高标准"，不是缺陷。而系统正在自我修正。**

---

## 1. 核心数字

| | `#10 赚大钱`（`ai_managed`，实盘） | `#11 [团队测试]`（`ai_team`，模拟） |
| --- | --- | --- |
| 有效轮次 | 592 | 137 |
| 有动作的轮次 | 277（**46.8%**） | 33（**24.1%**） |
| 决策总数 | 10,894 | 923 |
| 动作总数 | 320 | 44 |
| orders | 621 | 128 |
| trades | 192 | 41 |

**动作类型对比**（这里有一个值得注意的差异）：

```
#10: open_long 170 · open_short 68 · cancel_pending 35 · reduce_position 32
     · adjust_protection 10 · close_long 2 · close_short 3
#11: open_long  24 · open_short 19 · cancel_pending  1
     ⇒ #11 没有 reduce_position / adjust_protection / close_*
```

⚠️ 但那主要是**样本量**造成的（44 vs 320 条动作），不足以断言"团队模式不会调仓"。

## 2. skip 理由的分类（这是关键判据）

```
             #10（9,629 条 skip）      #11（870 条 skip）
A 数据不足类      420（ 4.4%）            94（10.8%）
B 规则拒绝类       65（ 0.7%）           203（23.3%）   ← 33 倍
C 其它          9,144（95.0%）           573（65.9%）
```

`#11` 的「规则拒绝类」是 `#10` 的 **33 倍** —— 而这不是数据缺失：

```
第236 轮 user_prompt 60,601 字，其中：
  含「D=」 15 次 · 含「ATR」 39 次 · 含「EMA」 80 次
⇒ 算 D 所需的数据【是够的】
```

### 2.1 `|D|` 落在策略师窗口内、却被 skip 的 46 条，逐条归类

| 理由 | 条数 | 是否规则内 |
| --- | --- | --- |
| 动量反转（理由 iii） | 21 | ✅ |
| 走法已成熟（理由 ii） | 13 | ✅ |

| 未归类 | 2 | ✅（逐条看过：证据链不完整） |

**⇒ 0 条是"绕过规则"。**

## 3. 策略师在自我修正（这是系统在正常工作的证据）

`set_params` 在最近 200 条 run 里出现 **20 次**。它的原话（`agent_runs` 的 `agents_json`）：

```
「5 consecutive idle cycles with zero trades. From recent_decisions,
  the D window [0.8%, 2.5%] is producing almost zero qualifying setups」

「结论：将 D 上限从 2.5% 提升到 5.0%。只改这一个参数，一次验证。」

「不是门槛不可达（minConfidence=0, minRiskRewardRatio=0, minPositionSize=5 都不是瓶颈），
  而是裁决官在 cycles 188-193 中系统性绕过入场规则」
```

⚠️ **最后那条指控我没有证实**（见第 2.1 节：46 条逐条归类，0 条绕过）。
它是策略师**当时的判断**，而数据显示裁决官在执行规则。

**窗口的演进痕迹**（从 skip 理由里抽取）：

```
0.8-2.5  39 次  →  2.5  22 次  →  3.5  8 次  →  0.8-3.5  7 次
```

⇒ 它在**主动放宽**，并且每次都记录了理由。这正是"由智能体负责风格"的设计意图。

## 4. ⚠️ 我在这次分析里犯了 3 次判据错误（如实记录）

```
① "账本 vs 全账户流水" 差 43.75 → 差点照它改数据
   真相：账户有 #10 创建【之前】的历史成交。正确判据是【同一个时间窗】

② 角色提示词用"首 40 字符"做签名 → 10 个角色完全相同（都是 COMMON 前缀）
   ⇒ 假阳性（检查它等于检查"有没有拼任何 ROLES 的 system"）

③ 【本次】判断"裁决官绕过规则"时，我用
   /理由\(iii\)|动量反转|盈亏比|RR|反向|末根/ 判"规则内"
   ⇒ 把下面这些都判成了"规则外"：
       第170「cycle cap 2 takes AVA first, so skip by throttle」← 持仓数上限
       第175「hard constraint blocks re-entry of ARC for 10min」← 冷却
       第185「direction confirm fail」                          ← 英文措辞
   ⇒ 26 条"疑似绕过"里，逐条看样本后【没有一条成立】
```

**共同形态：判据不能区分"我要检查的东西"与"别的东西"。**

③ 的具体教训：**判据不能只认"我预想的措辞"** —— 模型会用同义表达
（中文/英文/不同句式）。正确做法是**正向列举语义类别**，而不是匹配几个关键词。

## 5. 结论与建议

### 5.1 这不是缺陷

```
· 策略师定的规则（D ∈ [0.8%, 3.5%] + 方向确认 + 盈亏比 + 入场位）确实偏窄
· 但裁决官【在执行它】，没有绕过
· 而策略师【自己发现】了这个问题并主动放宽窗口
⇒ 这正是用户需求 ③ 想要的形状：
  「风格也应该由一个智能体来负责，而不是系统内置简单风控规则」
```

### 5.2 我**不建议**为了"增加动作"而改代码

那会变成**用内置规则替 AI 做决定** —— 与需求 ③ 直接冲突。
该做的是让 AI 的判断更准，而这次已经做了两件事：

```
① 补齐了 7 个角色的系统提示词（2026-10-15）——
   其中 judge 的提示词里明确写了：
     「skip 是正当结论，但不是默认结论」
     「判断标准是"依据够不够"，不是"哪个方向更安全"」
   ⇒ 这直接针对"动作率偏低"的成因，而且是【提示词】层面的修正，
     不是代码层面的硬规则
② 修复了"复盘从未生效"（agent_memory #11 从 0 → 2 行）——
   只有能学习，策略师才可能持续修正自己的规则
```

### 5.3 怎么验证 ① 真的改变了行为

```
判据（部署后观察 N 轮）：
  · #11 的"有动作轮次占比"是否从 24.1% 上升
  · 更精确的判据：「规则拒绝类」skip 的占比是否从 23.3% 下降
  · 以及：策略师的 set_params 是否仍然在调（说明它还在自我修正）
⚠️ 样本要够：至少 30 轮，否则与噪声无法区分（这个仓库的既有纪律）。
```

## 6. 我没验证成的部分（诚实列出）

- **"动作率上升是否等于更好"**：动作多不等于赚钱。`#11` 累计净 +0.15 USDT（41 笔），
  样本太小，**无法判断策略质量**。动作率只是一个"是否在工作"的指标，不是"是否赚钱"的指标。
- **`#10` 与 `#11` 的对照不是严格实验**：两者模型路径不同（一个走团队、一个走单模型）、
  账户不同、时间窗不同。24.1% vs 46.8% 的差**不能单独归因**于提示词或规则。
- **`D` 的抽取只覆盖"理由里写了 D 的"**（171 条 / 870 条 skip）。其余 699 条没有 D 值，
  所以第 2.1 节的分类**只对那 46 条有效**，不能外推到全部 skip。
