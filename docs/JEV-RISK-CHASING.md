# Jev 的「追高」风险 · 实测与判断

> 2026-10-18 · 实验期间发现的风险，不是 bug，但必须记住。

## 现象

Jev 的保留名单**高度重复**（最近 12 轮）：

```
QUSDT    6/12 次      ← 24h +109.86%（已翻倍）
BTWUSDT  6/12 次      ← +15.84%
AVAUSDT  5/12 次      ← +31.56%
GTCUSDT  5/12 次      ← +24.43%
AGTUSDT  5/12 次      ← +0.38%
```

而团队策略的入场标准是：
```
位移 D 在 0.8% ~ 3.5% 之间（ATR ≤ 3.5%）
```

⇒ **QUSDT +109%、AVA +31%、GTC +24% 全部远超 3.5% 的上限。**
**Jev 在挑"已经涨完"的标的。**

## 为什么会这样（不是 Jev 的错）

我给 Jev 的 instructions 是「挑出**今天有波动**的标的」。
而"波动大"在 24h 尺度上**同时包含**：
```
① 刚启动的行情（D 在 0.8~3.5% 窗口内）    ← 我们想要的
② 已经走完的行情（D 已超 3.5%）            ← 我们不要的
```

Jev 只看一眼摘要，无法区分这两者 —— 而它选 ① 和 ② 都是"有波动"。

**⇒ 这是我给的提问太粗糙，不是 Jev 的能力问题。**（同一类错误我之前犯过一次：
第一版提问是"值得深看吗"，改成"按四个数字排序"。）

## 但实测表明：**风险被下游挡住了**

### 团队今天的实际决策

```
周期 545-549 的决策：ZECUSDT open_long（止损 1123.01 / 止盈 1180.01，置信 65）
                     ← 不是 QUSDT，也不是 AVA
```

### 这些"追高"标的的实际结果

```
GTCUSDT  1 笔  +0.1268 USDT
AGTUSDT  1 笔  -0.0055 USDT
（QUSDT / AVA / BTW 今天没有成交）
```

**⇒ LLM 深看之后正确地放弃了它们。**

### 为什么会被挡住

```
Jev（初筛）：只回答"哪个波动大"     → 挑出 Q/AVA/GTC/BTW
    ↓
LLM（深看）：读完整材料，判断"这个位置还能不能进"
              → 发现 QUSDT 已涨 109%，ATR 远超 3.5%
              → skip
    ↓
风控（裁决）：位移/ATR/盈亏比/置信度四道门槛
              → 就算 LLM 想进也会被拦
```

**这就是分层设计的价值：初筛只需要"粗筛"，不需要"准"。**

## 判断：**不构成移除的理由，但必须监控**

| 问题 | 判断 |
|---|---|
| Jev 在追高吗 | **是** |
| 这会导致团队追高吗 | **没有证据表明会** —— 下游两层都没让它过去 |
| 需要修吗 | **不修 Jev**（它只能看到摘要，分不清"刚启动"与"已走完"）。真正的门槛在下游，而下游工作正常 |
| 需要监控吗 | **必须**。如果哪天 LLM 真的去追了，那是下游失守，不是 Jev 的问题 |

## 但有一个改进机会

既然 Jev 的分数与"波动大小"高度相关，而我们要的是**"波动在窗口内"**，
可以在 **digest 里显式给出窗口判断**，让它不用自己算：

```
现在的 digest：  current_price / ema20 / 24h_change / ATR / RSI / 最近5根
建议加上：       "窗口判断：D=-1.05%（在 0.8~3.5% 内）· ATR=1.0%（≤3.5%）"
```

**但这属于"给 Jev 喂更多信息"，需要单独验证**（TypeSafe 官方明确说
"长、噪声多的上下文会降低准确度"）。**不在本次实验范围内，记为后续可选改进。**

## 结论对实验判定的影响

**不影响"保留"这个结论**，因为：
1. 判据（保留 vs 筛除的波动对比）仍然成立 —— Jev 确实在挑"动的"
2. 追高的代价被下游挡住，未体现在实际盈亏上
3. 移除它反而会让 LLM 重新分析全部 20 个标的（耗时从 120s 回到 300s+）

**但要加一条监控判据**：
```
如果连续 N 轮"Jev 保留的标的"里，超过一半的 24h 涨跌幅 > 10%（已走完），
说明它在系统性地追高 —— 那时应该：
  ① 先看团队的决策有没有真的跟进（跟进才是问题）
  ② 若没有跟进：说明分层工作正常，可以继续留着
  ③ 若跟进了：关掉 Jev
```

## 追加验证（10:50）· 一个重要的认知修正

### 我原来的理解（不完整）

我以为 Jev 筛掉某个标的 = 那个标的不会进 LLM 视野。
**错了。**

### 实际的架构

```
Jev 只影响【逐币深看】那一层（slicesForLlm）
      ↓
逐币深看的产出是【补充材料】，追加在裁决官的材料里：
      `## 按币并行分析（每个标的的独立评估，含完整序列）`
      ↓
而裁决官【同时】还看完整的市场材料（由分析师提供，不经过 Jev）
```

**⇒ 所以 Jev 筛掉 ZEC，不会阻止团队做 ZEC。它只是让 LLM 少一份 ZEC 的深度分析。**

### 实测证据

```
02:37  ZECUSDT hold       （ZEC 不在 Jev 保留名单）
02:22  ZECUSDT open_long  （ZEC 不在 Jev 保留名单）
02:06  ZECUSDT skip
02:01  SANDUSDT open_long （SAND 在保留名单）
```

**4 次开仓决策里 2 次来自"Jev 没保留"的标的** —— 说明下游仍有完整视野。

### 这带来两个结论

**① 好消息：Jev 不会"掐死"任何标的。** 它只是减少了深度分析的覆盖。
   ⇒ **风险比我以为的低得多。**

**② 坏消息：Jev 的收益也比我以为的小。** 它省的是"逐币深看的调用次数"（20 → 6），
   不是"LLM 看到的标的数"。裁决官那一路的开销没变。

   ⇒ 这解释了为什么耗时从 308s 只降到 **105–137s（↓55%~66%）** 而不是更多
     —— 省下的是逐币那一大块，其余（分析师/辩论/裁决）不变。

### 对"保留"结论的影响

**不改变结论，但把它说得更准确：**

> Jev 的价值是**把逐币深看的成本砍掉 70%**（20 → 6 个标的），
> 用的是"挑波动大的"这个粗糙但有效的启发式。
> 它**不决定**团队做什么 —— 那由 LLM + 风控决定。
> 它的风险是"追高倾向"（68% 的保留标的是已走完行情），但该风险**不传导到交易**，
> 因为下游仍有完整视野。

### 因此，改进空间在哪

如果想让 Jev 真正提升**质量**（而不只是省钱），必须让它**参与裁决**——
但那需要它输出文字理由，而它**不产生文字**（见 `JEV-EXPERIMENT.md` §2）。
**⇒ 这是它能力边界，不是调参能解决的。**

**⇒ 结论：Jev 的正确定位就是"便宜的初筛"，不要期待它提升决策质量。**

## 追加（11:00）· 系统性歧视：一个混合信号

### 现象：Jev 的判定几乎确定，不是"每天重新判断"

14 轮样本里：

```
永远被筛掉（0% 保留率）：
  SOLUSDT   14/14 次被筛
  WLDUSDT   14/14
  TIAUSDT   14/14
  ETHUSDT   14/14
  HYPEUSDT  12/12
  SIRENUSDT 12/12
  ICNTUSDT  11/11
  XRPUSDT   11/11

永远被保留（100%）：
  QUSDT     9/9
  GTCUSDT   7/7
```

**⇒ 它对同一个标的给出几乎相同的分数。** 所以"每天重新判断"这个说法不成立 ——
**它实际上是在按标的的固有属性（波动率水平）打一个固定分。**

### 这意味着什么（好坏参半）

**风险：被歧标的的逐币深度分析永久缺失。**

```
TIAUSDT  历史 5 笔  +0.5113  ← 历史最赚，但 Jev 从不保留
WLDUSDT  历史 5 笔  +0.3252  ← 第二赚，同样从不保留
```

**⇒ 如果 TIA 哪天有大行情，Jev 会把它筛掉，团队少一份它的深度分析。**

**但也有正面数据：**

```
高保留率组(≥50%): 6 个标的，平均净盈亏 +0.1408
低保留率组(<50%): 13 个标的，平均净盈亏 +0.0327
                  ⇒ 高保留率组更赚 4.3 倍
```

**⇒ 整体上 Jev 的歧视是"对"的**（它保留的那批确实更赚钱），
但局部的错误很扎眼（漏掉 TIA / WLD 这两个历史赢家）。

### 完整的保留率 × 盈亏对照表

| 标的 | 保留率 | 历史净盈亏 |
|---|---|---|
| QUSDT | 100% | **+0.4185** |
| GTCUSDT | 100% | +0.1268 |
| BRUSDT | 78% | +0.1091 |
| SANDUSDT | 64% | +0.1091 |
| BTWUSDT | 50% | +0.0814 |
| NEARUSDT | 36% | +0.0525 |
| AVAUSDT | 36% | -0.1332 |
| AGTUSDT | 27% | +0.1799 |
| ZECUSDT | 22% | **-0.4383**（最亏） |
| SOLUSDT | 0% | +0.0734 |
| WLDUSDT | 0% | **+0.3252**（漏掉） |
| TIAUSDT | 0% | **+0.5113**（漏掉，最赚） |

**注意 QUSDT（100% 保留，最赚之一）与 ZECUSDT（22% 保留，最亏）—— 这两个判对了。**
**而 TIA / WLD 判错了。**

### 判断：**不改结论，但降低信心**

| 问题 | 判断 |
|---|---|
| 歧视本身 | 真实存在 |
| 影响有多大 | **混合**：整体上对（4.3 倍差异），局部错（漏 TIA/WLD） |
| 会不会导致漏钱 | **可能**。但注意：Jev 只影响逐币深看，裁决官仍看完整材料（见上一节）⇒ **漏分析 ≠ 漏交易** |
| 该移除吗 | **不该**。它的净效果是正的，而且移除会让耗时回到 308s |

**⇒ 但必须记住这条：Jev 有"永久性偏好"，不是动态判断。
  如果哪天它的偏好与市场风格脱节（例如市场从高波动转向低波动），
  它会把所有标的都筛掉 —— 那时判据里的"比值"会崩，复核脚本会报警。**

### 已经加进复核脚本的检测

`scripts/jev-review.sh` 的 §2b 现在会报：
```
保留组里 24h |涨跌| > 10% 的占比（追高倾向）
```
**下一版应该再加一条：**「0% 保留率的标的有几个」——
当这个数超过总数的一半时，说明 Jev 的偏好已经覆盖不了市场。
