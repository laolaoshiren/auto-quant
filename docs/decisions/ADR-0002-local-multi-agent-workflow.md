# ADR-0002：本地多 Agent 工作流（分支 + 完成标记 + 单点合并）

- **状态**：已采纳
- **日期**：2026-11-09
- **决策者**：用户（明确"个人项目、无外部 PR、追求效率"）与 AI 共同确定

## 背景

项目需要多线并行开发（UI、功能、PR 处理等），但 GitHub PR 流程对个人项目是额外成本；
同时 GitHub 账号曾有封号事故，需避免高频 `gh` 调用。

## 选项

| 选项 | 优点 | 代价 |
|---|---|---|
| A. 全部走 GitHub PR | 平台门禁/记录 | 高频 API、封号风险、个人项目无必要 |
| B. 多窗口各自直接改 main | 无合并成本 | 互相覆盖、冲突不可控 |
| C. 分支 + 完成标记 + 单点合并 | 隔离、可控、零平台依赖 | 需要一条"集成线"做合并与验证 |

## 决定

采用 **C**：

1. **开发线**（窗口/工作树/Agent Team 队友）只改自己的分支，自测绿后打完成标记（tag 或 `ready` 文件），
   不直接推 main。
2. **集成线**（一个固定窗口/角色）按顺序串行合并，每条合并后跑全量验证；全绿才推 main。
3. **推送**：main 只由集成线推；大的/多天的迭代可自行推（用户 2026-11-09 授权），小的等用户安排。
4. **PR 的使用边界**：仅当①对方无仓库写权限（fork/外部贡献者）或②需要平台审查记录时使用；
   有写权限的同账号机器只推分支。
5. **7×24 定时任务**：用低频定时唤醒（如每 10–60 分钟），单次调用、禁止循环轮询 `gh`；
   任务只提交分支/写报告，合并仍由集成线做。

## 影响

- 合并是串行的，这是 Git 的本质，不是效率损失。
- 依赖"纪律"而非平台强制：写作用域不重叠、main 单点推送、失败即停。
- 若未来有外部贡献者，A 作为补充通道启用。
