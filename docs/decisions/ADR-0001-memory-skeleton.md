# ADR-0001：项目记忆骨架（文件 + 协议 + 每周对账）

- **状态**：已采纳
- **日期**：2026-11-09
- **决策者**：用户提出目标（长期开发不丢关键信息、新窗口能接上），AI 设计并落地

## 背景

项目经历多轮长会话后出现「目标漂移 / 交代的事情被遗忘」。根因不是模型记性，而是：

- 目标、进度、决策只存在于对话里，上下文压缩或换窗口后消失；
- 项目虽有 `AGENTS.md`（每轮加载）与 `.dsh/PROJECT-CONTEXT.md`（2026-09-30 旧快照），
  但前者只装规则、后者已过时且没有"每轮读写"的强制协议；
- `.dsh/` 里还有 335KB 台账等大文件，新会话无法判断该读哪份。

## 选项

| 选项 | 优点 | 代价 |
|---|---|---|
| A. 装记忆插件 / 换 harness | 省事 | 解决不了"状态外置"；插件多为摘要，仍失真；迁移成本高 |
| B. 只靠对话 | 无成本 | 已被证明会漂移 |
| C. 文件 + 协议 + 定期对账 | 不依赖工具、可审计、换 harness 仍有效 | 需要每轮维护（收尾 4 步） |

## 决定

采用 **C**，建立三层记忆：

1. **长期（入库）**：`docs/PROJECT-GOALS.md`（目标，少变）、`docs/decisions/ADR-*.md`（决策追加）。
2. **中期（本地）**：`.dsh/state.md`（每轮更新）、`.dsh/ledger/OPEN.md`（未闭环任务）、
   `.dsh/ENGINEERING-LESSONS.md`（可复用教训）。
3. **入口（本地）**：`.dsh/START-HERE.md`（60 秒开场协议 + 指针表）。
4. **强制机制**：根 `AGENTS.md`（每轮自动加载）写死"新会话先读 START-HERE"；每轮收尾更新 state；
   每周一次"目标对账"（读 GOALS + state + git log，输出偏差报告）。

## 影响

- 每轮多花约 1–2 分钟读写文件；换来换会话/换工具都能恢复。
- 不追求"永不忘"，追求"遗忘可发现、状态可恢复"。
- 旧文件 `PROJECT-CONTEXT.md` 保留为历史快照，不再作为入口。
