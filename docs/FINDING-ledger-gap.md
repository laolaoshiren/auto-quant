# 总账校验的 −0.2 差额：已排查什么、还剩什么

## 现象

`/data` 页报两条 `ERROR`（阈值 0.01 USDT）：

```
账目与交易所对不上：平台记录 -2.8691、交易所流水 -2.6666，差 -0.2026   （机器人 #4、#5）
账目与交易所对不上：平台记录 -3.1412、交易所流水 -2.9450，差 -0.1962   （机器人 #6）
```

而同一个交易所账户上，另外两个机器人正常：

```
机器人 #7  gap = -0.0064  ✅
机器人 #8  gap = +0.0057  ✅
```

**账户是同一个**（`income` 流水、订单都共享），五个机器人里三个报差、两个不报。

## 口径

```
gap = platformNet − exchangeNet
platformNet = platformSelf + foreignNet
              └ 全部机器人的 trades 净额（窗口内）
                              └ 账户上"不属于本平台任何机器人"的成交净额
exchangeNet = 交易所 income 流水中 REALIZED_PNL + COMMISSION + FUNDING_FEE（窗口内）
```

分项已经落进 `settings.ledger_check:<id>`（本轮新增），可以直接看：

| 机器人 | platformSelf | foreignNet (n) | platformNet | exchangeNet | gap |
|---|---|---|---|---|---|
| #4 | −0.542167 | −2.32694 (195) | −2.869107 | −2.666555 | **−0.2026** ❌ |
| #6 | −0.8143 | −2.32694 (195) | −3.14124 | −2.945023 | **−0.1962** ❌ |
| #7 | −0.141709 | −2.663027 (223) | −2.804736 | −2.798288 | −0.0064 ✅ |
| #8 | +0.324598 | −2.65092 (222) | −2.326322 | −2.331982 | +0.0057 ✅ |

## 已排除（两处，都已修，但都不是这个差额的成因）

### 1. `foreignNet` 漏算资金费 —— 修了，`gap` 没变

`foreign.push` 原来写 `grossPnl - entryFee - exitFee`，少了 `funding`；而 `exchangeNet`
那一侧的资金费是计入的。这是**真实的口径不一致**，已补上（提交见 `git log`）。

**但它不是这个差额的成因**：补上之后 `gap` 与 `foreignNet` 一个数字都没动 ——
说明这些外部回合在本窗口内的资金费恰好是 0。

### 2. `foreign` 的扫描范围是"本机器人级"而非"账户级" —— 修了，`gap` 仍然没变

`symbols` 原来由 `tradedSymbols(traderId)` + `positions.open(traderId)` + `income` 符号构成，
而"外部活动"本质是账户级概念。已改为 `allTradedSymbols()` + `allOpenSymbols()`
（新增两个仓储方法，`repositories.ts`）。

**但 `foreignRounds` 仍然是 195 / 223**，一个都没多 —— 说明**账户级比本机级并没有多出符号**，
即 `trades` 表里存在的符号集合本来就是账户级的那些。

## 还剩什么没查

**关键未解的事实**：`#4/#5/#6` 收到 **195** 笔外部活动，`#7/#8` 收到 **222/223** 笔。
`allOrders`（`orderStore.allExchangeOrderIds()`）是**全局**的，`symbols` 现在也是**账户级**的
—— 两边本该数出同一批外部回合，却差 27 笔。

因此下一步应当验证的是**这 27 笔去了哪里**，具体做法（按代价从低到高）：

1. **把 `symbols` 的大小与内容也落进 `ledger_check`**（几行代码），确认五个机器人扫的是同一组符号。
   现在的 `skipDiag = {beforeWindow, otherTrader, foreign, foreignNoId}` 只数了结果，没数输入。
2. **确认 `since` 的实际值**。`since = deep ? createdAt − 60s : max(createdAt − 60s, now − RECONCILE_WINDOW_MS)`。
   `#4/#5` 创建于 09-18、`#6` 创建于 09-16 —— 若 `/reconcile` 走的是 `deep`，三者的窗口起点
   相差两天，而 `beforeWindow` 只有 3/3/6 笔，看起来不像主因，但**没有直接打印过 `since`**。
3. **逐笔对**：把 `income` 流水与 `trades` + `foreign` 按 `(symbol, 时间)` 对齐，
   找出落在 `exchangeNet` 里、却不在任何一侧 `platform` 里的那些条目。这需要一次
   带诊断输出的对账（`getIncome` 的结果不落库，必须在进程内比对）。

**注意**：`income` 流水**不落库**，所以第 3 步必须改代码在一次运行里同时拿到两侧数据 ——
现有数据不足以在事后从库里算出答案。

## 影响面

- 只影响**共用同一账户的多个机器人**之间的归属划分，不影响单机器人账户（`#7/#8` 的
  `gap` 是浮点级，说明正常路径下这套校验是准的）。
- `#4/#5/#6` 都是 `stopped` 的测试机器人；`#8`（AI 托管实盘，真金白银）`gap = +0.0057` 正常。
- **这不影响下单与风控**（那两条路径不经过这段代码），它是**账本校验的告警**。
  但因为差额恒定存在，**它每轮对账都会重报** —— 而这正是这段代码自己的注释警告过的
  「一个永久误报的校验会训练操作员忽略这条告警」。
