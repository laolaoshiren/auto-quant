# auto-quant

**一个 7×24 全自动的 LLM 驱动加密货币合约量化交易终端。**

---

## 🚀 一条命令部署

在服务器上（需要 Docker）：

```bash
cd /opt/autoquant/deploy && ./up.sh
```

**就这一条。** 它会自动生成配置与密钥、拉取镜像、启动服务、等待健康检查通过，
最后告诉你访问地址和登录密码。

之后每次更新版本，**还是这一条命令**。

- 不需要在服务器上装 Node
- 不需要克隆源码、下载依赖、构建前端
- 服务以 **Docker 镜像**运行，镜像由 GitHub Actions 在 CI 通过后自动构建

> **首次使用前的一次性准备**（因为仓库是私有的）：
>
> ```bash
> git clone --depth 1 https://github.com/laolaoshiren/auto-quant.git /opt/autoquant
> cd /opt/autoquant/deploy && ./up.sh
> ```
>
> 之后 `deploy/` 目录就是全部的部署材料，源码不再需要。

## 这是什么

策略本身就是一段自然语言。每个交易机器人循环执行「读取市场结构 → 决策 → 下单 → 记录推理」，
而一个独立于模型的 **硬风控引擎** 会拦截并钳制它发出的每一张订单。

> **当前阶段**：交易所只对接 **币安 USDT 本位合约（USDⓈ-M）**。
> 核心能力是「自然语言策略 + 硬风控 + 完整决策审计」这三件事的组合。

## ⚠️ 风险提示

**自动交易会造成真实资金损失。** 本项目默认运行在**模拟盘（paper）模式**，且默认连接币安 **Demo 环境**。
在切换到实盘之前，请务必：

1. 先在模拟盘上跑够时间，确认策略与风控行为符合预期；
2. 使用**只有合约交易权限、禁止提现**的 API Key，并绑定 IP 白名单；
3. 先用最小资金验证；
4. 不要投入你无法承受损失的资金。

## 快速开始

环境要求：**Node.js ≥ 22.5**（用到内置的 `node:sqlite`，无需编译原生模块）。

```bash
# 1. 安装依赖
npm install

# 2. 启动后端（首次启动会创建 owner 账号并打印随机密码，只显示一次）
npm run dev
```

启动后访问 **http://127.0.0.1:3200**。首次启动请记录控制台打印的 `admin` 密码。

```bash
# 3. 前端开发服务器（可选，热更新）
npm run dev:web        # http://127.0.0.1:5173，已配置 /api 代理

# 4. 生产构建
npm run build && npm start
```

### 用真实币安数据验证整条流水线

不需要交易所密钥、也不需要 LLM Key，即可验证「选币 → 指标 → 提示词 → 解析 → 风控」全链路：

```bash
npm run verify
# 或：npx tsx packages/server/src/scripts/verifyPipeline.ts
```

它会连接币安、拉取真实 K 线、计算指标、生成两段提示词、
解析一份示例模型响应，并让风控引擎审查它 —— 全程不下单。

### 完整交易生命周期模拟（推荐先跑这个）

用**真实历史 K 线回放**驱动一个**会真正触发止损止盈的模拟交易所**，
跑完整条链路（提示词 → 模型 → 解析 → 风控 → 下单 → 保护单 → 触发 → 记账）：

```bash
npm run sim                 # 脚本化模型，80 轮决策，15 项校验
npm run sim -- --cycles 120 # 更长回放
npm run sim:live            # 用真实 LLM 跑（需先设置 SIM_LLM_KEY 环境变量）
```

脚本化模式会**刻意安排**覆盖每一条执行路径：紧止损（必然被价格触发）、
宽止损（由模型主动平仓）、以及故意超限的提案（100x 杠杆、过低置信度），
用来证明风控的钳制与拦截真的在链路上，而不是仅仅被配置了。

它写入临时数据库，**不会碰你的真实数据**。

### 实盘冒烟测试（部署后第一件事就是跑它）

模拟证明的是**逻辑**，只有这个能证明**接线**。它会用交易所允许的最小仓位
完整走一遍：预检 → 单向模式 → 杠杆 → 市价开仓 → 挂止损 → 挂止盈 →
回读交易所确认保护单真的挂着 → 撤单 → 平仓 → 确认账户干净。

```bash
# 从数据库里读凭据（默认取第一个账户）
npx tsx packages/server/src/scripts/liveSmokeTest.ts --confirm

# 或用环境变量
BINANCE_API_KEY=xxx BINANCE_API_SECRET=yyy \
  npx tsx packages/server/src/scripts/liveSmokeTest.ts --confirm --symbol DOGEUSDT --notional 6
```

安全设计：**必须有 `--confirm` 才会下单**；名义价值硬性上限 20 USDT；
清理步骤写在 `finally` 里，中途异常也会平仓撤单；结束时回读交易所确认账户干净。

> **它会真的花钱。** 先用最小仓位，确认无误再放大。

## 部署（从源码部署，开发/调试用）

> **常规部署请用最前面的「一条命令部署」** —— 服务以 Docker 镜像运行，
> 服务器上不需要 Node，也不需要源码。本节只适用于**需要改代码**的场景。

币安对 API Key 有 **IP 白名单**限制：本机 IP 不在白名单里时，所有签名请求都会返回
`-2015`，**无法下单**（公开行情接口不受影响）。所以实盘必须部署到已加白的机器上。

```bash
pwsh -File scripts/deploy.ps1 -Server <你的主机>
```

`-Server` 是 ssh 别名或 `user@host`。常用值可以写进 `deploy.local.ps1`（已 gitignore）：

```powershell
@{ Server = 'my-server'; RemoteDir = '/opt/autoquant'; PublicUrl = 'https://quant.example.com' }
```

> 部署脚本里**不含任何站点专属信息**（主机、域名、路径）。那些属于部署者自己的环境，
> 不属于项目代码。

**部署脚本的关键设计**：打包时**排除 `.env`**。这一点非常重要——漏掉它会让本地开发配置
覆盖服务器的实盘配置，**服务会静默切到模拟盘**：不报错，只是所有交易悄悄跑到错误的环境上。
所以排除列表固化在脚本里，并在解压后回显 `.env` 状态。

完整的部署指南（Docker 方式、systemd、反向代理、HTTPS、安全检查清单）见
**[docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)**。

> **安全提醒**：控制台登录后能下真实订单。若暴露到公网，除强密码外建议再叠加一层——
> 反向代理的 `basic_auth`、Cloudflare Access、或 IP/国家限制。

### 立即看到「决策记录」界面

决策审计界面需要数据才有意义，但产生数据通常要先有交易所密钥和 LLM Key。
这个脚本用**真实行情 + 真实指标 + 真实提示词 + 真实解析 + 真实风控**，
配上**模拟交易所**和**脚本化模型**，跑完整一轮并写入数据库：

```bash
npx tsx packages/server/src/scripts/demoCycle.ts          # 生成演示数据（全部带 [DEMO] 前缀）
npx tsx packages/server/src/scripts/demoCycle.ts --clean  # 一键清除
```

它会创建一个 `[DEMO] 决策审计示例` 机器人，含 1 个持仓、3 张订单
（入场 + 交易所侧止损 + 止盈）和 1 条完整决策记录。打开控制台即可看到
思维链、解析后的决策、逐条执行结果，以及完整的系统/用户提示词。

**全程不向交易所发送任何请求。**

## 从零到实盘的操作路径

**第 1 步 · 拿到交易所 API Key**

去币安创建合约 API Key，然后：

- ✅ 勾选「启用合约」
- ❌ **不要**勾选「启用提现」
- ✅ 绑定服务器 IP 白名单
- 建议先创建一套 **Demo 环境**（<https://demo.binance.com>）的 Key，先用它跑通

**第 2 步 · 在控制台填入凭据**

`设置 → 交易所账户 → 新增`，填入 Key/Secret，勾选「使用测试网」（Demo 环境）。
保存后点 **Test connection**，它会逐项报告：凭据有效性、余额、合约权限、仓位模式、时钟偏移。

**第 3 步 · 配置 LLM**

`设置 → AI 模型 → 新增`，从下拉里选提供商（会自动填好 Base URL 与推荐模型），
填入自己的 API Key，然后点 **Test**。

> 提供商与模型名可随时修改。模型名是自由文本，厂商更新模型后无需改代码。

**第 4 步 · 编辑策略**

`策略工作室`，从三个预设（稳健 / 进取 / 短线）之一开始，然后按需调整：

- **选币**：静态列表 / 动态筛选（流动性、涨幅、跌幅、波动、资金费极值）/ 持仓量增长 / 混合
- **指标**：时间周期组合、蜡烛数、EMA/MACD/RSI/ATR 参数、是否启用成交量/持仓量/资金费/主动买卖流
- **风控**：最大持仓数、BTC/ETH 与山寨币分别的杠杆上限与名义价值倍数、
  保证金占用上限、最小下单量、最小盈亏比、最低置信度、是否强制止损止盈
- **回撤守卫 / 节流 / 熔断**：回吐平仓、最小持仓时间、再入冷却、每轮/每小时开仓上限、单日亏损与总回撤上限
- **提示词四段**：角色、交易频率、入场标准、决策流程 —— **策略本身就在这里**
- **自定义提示词**：追加在系统提示词末尾

**第 5 步 · 创建机器人并启动**

`总览 → 新建机器人`，选好凭据、模型、策略和周期（分钟）。
点启动后先选 **模拟（Paper）** 跑一段时间；确认无误后再选 **实盘（Live）**。

**第 6 步 · 观察与审计**

- `机器人看板 → 决策` —— 每一轮的思维链、完整提示词、逐条执行结果
- 被风控拒绝的提案会标红显示理由（这是"为什么它什么都没做"的答案）
- 持仓卡片上如果没有止损会显示警告徽章
- `数据` 页看实时日志；`MARGIN_CALL` 会以错误级别出现

**随时可用的安全阀**

- 机器人卡片上的 **Stop**（一键停止）
- `GLOBAL_TRADING_DISABLED=true`（拒绝启动任何机器人）
- `DRY_RUN=true`（读真实行情与账户，但不真正下单）

## 配置

复制 `.env.example` 为 `.env`。关键项：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `3200` | 控制台端口 |
| `BINANCE_USE_TESTNET` | `true` | `true` = 币安 Demo 模拟盘；`false` = 实盘 |

## 盈亏口径与对账

**平台显示的盈亏必须和交易所账户一致，这不是靠小心，是靠结构。**

### 口径

| 字段 | 含义 |
|---|---|
| `pnl` | **毛盈亏**，直接取交易所的 `realizedPnl`，不由平台重算 |
| `entryFee` / `exitFee` / `fee` | 开仓侧、平仓侧、以及合计手续费 |
| `fundingFee` | 资金费（每 8 小时结算，任何成交记录里都看不到） |
| `netPnl` | **净盈亏 = 毛 − 手续费 − 资金费**，这才是真正影响余额的数字 |
| `source` | `bot`（运行期实时记账）或 `reconciled`（从交易所成交历史补录） |

`TraderStats.realizedPnl` 是**净**值；毛值在 `grossRealizedPnl`。

### 为什么需要"对账"

平台过去只有在**自己活着的时候**才能观察到平仓：要么它自己下的平仓单，要么下一轮
周期发现仓位不见了。两条路都要求周期在跑。于是——

> 交易所侧止盈触发时进程已停 → 这笔平仓**永远不会被记账**。

实测后果：一笔 POWERUSDT 131 张、**+0.6563** 的盈利回合完全缺失，账面显示
**−0.3136**，而账户实际是 **+0.2586**。不只是不准，是**符号相反**。

### 对账做什么

`reconcileTradeHistory()` 从 `/fapi/v1/userTrades` **重建完整回合**，并与本地台账比对：

- **补齐**：本地没有的回合 → 补录（`source: reconciled`，平仓原因记为 `对账补录`）
- **修正**：本地有的回合 → 用交易所的数字覆盖毛盈亏与**双侧**手续费
  （旧实现只记了平仓一侧，手续费少了一半）
- **归属闸门**：只有**本机器人下过单**的回合才会被认领（用入口订单号匹配）。
  多个机器人共用一个交易所账户时，成交历史对它们是相同的——没有这道闸门，
  每个机器人都会把账户的全部盈亏记到自己头上，实际发生过。

**幂等**：重复执行不会重复插入，只会修正。

**运行时机**：服务器启动时对**所有**机器人执行一次（包括已停止的），以及每轮周期开头。
停止状态下也能从 UI 手动触发（`POST /api/traders/:id/reconcile`，不下任何单）。

### 对账结果（实盘验证）

```
平台记录的机器人净盈亏   = 0.272133160000
机器人之外的活动         = -0.013549500000   （早于机器人创建的冒烟测试）
────────────────────────────────────────
合计                     = 0.258583660000
交易所钱包实际变动        = 0.258583660000
差额                     = 6.66e-16          ← 浮点精度极限
```

对账后同时刷新权益快照，因此**已停止的机器人显示的权益也是当前真实值**，不会停在
最后一次运行周期时的历史数字上。

### 已知边界

- **资金费**依赖 `/fapi/v1/income` 可读；读不到时该项记 0 并在日志中说明，不会假装算过。
- **手续费以非结算资产计价时**（例如用 BNB 抵扣）不计入 `fee`——它和 USDT 不是同一个单位。
  这类费用会被单独报告，而不是悄悄加进一个口径不同的总数里。

| `/traders/:id/decisions/:recordId` | 决策审计详情：思维链、解析决策、逐条执行结果、完整提示词 |
| `/strategy` `/strategy/:id` | **策略工作室**：选币、指标、风控、回撤/熔断/节流、提示词四段、自定义提示词，以及 **策略体检** |
| `/models` | **AI 模型**：添加/编辑/测试，支持从厂商接口实时拉取可用模型列表 |
| `/exchanges` | **交易所**：添加/编辑/测试交易所凭据 |
| `/market` | 行情：搜索交易对 + K 线图（1m/5m/15m/1h/4h/1d） |
| `/data` | 实时日志（WebSocket 推送） |
| `/account` | 操作员账户：修改密码 |
| `/faq` | 使用说明与风险提示 |

启动机器人时可选择 **模拟（Paper，默认）** 或 **实盘（Live）**，
并会展示完整的启动前检查结果（阻塞项标红）。

### 添加 AI 模型：三步，其余全部自动

1. 选 **供应商**（Base URL 自动填好）
2. 填 **名称** 和 **API Key**
3. 点 **获取可用模型** —— 系统用你的 Key 直接向厂商拉取**当前可用**的模型列表，
   搜索选择即可；也可以手动输入模型 id

**为什么不做静态预设**：模型 id 更新极快，任何硬编码的"推荐列表"几个月后就会过时，
而过时的默认值只在运行时才报错——那是最糟糕的失败时机。实时拉取则永远是最新的，
还能顺带发现"Key 有效但无权访问该模型"这类问题。

温度、最大 Token、超时、重试次数都按供应商预填并收在**高级设置**里，通常不需要动。
保存前可以点 **测试连接** 先验证。

### 策略体检：不接交易所就能验证策略

在策略工作室点 **策略体检**，选一个已配置的 LLM 模型，系统会用**真实行情**
跑完整条链路，并逐阶段报告：

```
交易所连接与合约元数据 → 选出候选标的 → 组装行情与指标 → 构建提示词
→ 调用模型 → 解析模型输出 → 硬风控审查
```

它把两种截然不同的失败区分开来——这两者从外部看都是"机器人什么都没做"：

- **模型没答或答得无法解析** → 是提示词或模型选择的问题
- **模型答得挺好，但提案全被风控拒了** → 是风控限制与策略提示词不匹配

体检用的是**模拟账户**，全程不向交易所发送任何请求，因此**不需要交易所密钥**。

## 核心设计原则

### 模型提议，运行时裁决

模型输出被当作**不可信输入**处理。每一张订单都会经过 `src/risk/engine.ts`，
那里的限制**在代码里强制执行，模型无法覆盖**：

- 最大同时持仓数、每标的仅一仓
- 杠杆钳制（BTC/ETH 与山寨币分别设限，按名义价值计算，与模型请求无关）
- 名义价值上限（按账户权益倍数）
- 保证金占用上限
- 最小下单量与最小盈亏比、最低置信度
- **强制止损止盈**：开仓后立刻在交易所挂上条件单
- 回撤守卫：浮盈从峰值回吐过多时自动平仓
- 节流：最小持仓时间、同标的再入冷却、每轮/每小时开仓次数上限
- 熔断：单日亏损上限、总回撤上限、连续失败进入安全模式
- 币安全局「急停」开关

每一次钳制都会记录在决策审计里，账户所有者在控制台上能看到**运行时在哪里推翻了模型**。

### 完整可审计

每次决策都持久化 `systemPrompt`、`userPrompt`、模型的思维链、原始响应、
解析后的决策、以及逐条执行结果。**不存在没有纸质记录的仓位。**

### 关键工程决策（来自实测调研）

调研文档见 `docs/research/`。以下几条直接改变了实现，且都是"踩了会亏钱"的类型：

| 事实 | 影响 |
| --- | --- |
| 币安已于 2025-12-09 把条件单迁移到 `POST /fapi/v1/algoOrder`，`/fapi/v1/order` 对 `STOP_MARKET` 等直接返回 `-4120` | 止损止盈必须走 Algo Order API，参数名为 `triggerPrice` 而非 `stopPrice`；否则**开仓后根本挂不上止损** |
| Algo 订单是独立身份空间（`algoId`/`clientAlgoId`/`algoStatus`） | broker 层把两种订单归一化为统一的 `PlacedOrder`，交易循环无需分支 |
| `closePosition` 条件单在手动平仓后依然存活，会朝反方向开新仓 | 任何手动平仓前必须先撤销该标的的**全部**普通单与 Algo 单 |
| 合约 WebSocket 已按流量类别拆分路由（`/public` `/market` `/private`），旧路径 2026-04-23 停用；**错误路由会连接成功但永远收不到数据** | WS 层按路由表订阅，并实现**应用层存活检测**（协议层"已连接"不能证明有数据） |
| 测试网权重上限 6000/min，实盘 2400/min | 权重预算从 `exchangeInfo.rateLimits` 读取，不硬编码 |
| 测试网 `exchangeInfo.serverTime` 陈旧约 5 天 | 时间同步只用 `/fapi/v1/time`；启动时强制同步（实测本机漂移约 1 秒） |
| `MIN_NOTIONAL` 是**逐币种**的（BTCUSDT=50、ETHUSDT=20 等） | 从 `exchangeInfo` 过滤器读取并用于下单前校验 |
| 除 `-1021` 外，撮合引擎还有第二道 `recvWindow` 检查（`-5028`） | 两者都触发时钟重同步并重试 |
| 测试网 `/futures/data/*` 不可用（返回非 JSON） | OI 历史/OI 排行在模拟盘优雅降级为空，不报错 |

## 功能范围（第一阶段）

**已实现**

- 币安 USDT 本位合约全自动交易，7×24 循环
- 可配置：交易所凭据 / 交易策略（提示词策略）/ LLM 提供商 / 机器人（杠杆、风控、策略）

- 回测引擎
